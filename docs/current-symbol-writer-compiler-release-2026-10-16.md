# Current symbol writer compiler and clock preparation

Candidate `0.3.0+codex.20261016124500`. This continues the
[clock implementation](current-symbol-clock-implementation-2026-10-16.md).
It does not enable symbol editing or claim a connected writer test.

## Implemented

The existing disposable-project tool gains two typed, optional actions:

- `baseline-prepare-clock` consumes the original closed baseline before
  replacement launch. It selects the exact unlocked history-head date and runs
  the fixed current Date controls in a disjoint, source-qualified scratch
  process. It requires `acceptScratchProcessEffects:true` and accepts no code,
  literal, target, path or supplied result. A failed attempt prevents relaunch.
- `baseline-observe-clock` runs fixed Date controls in that same baseline's
  original project-only replacement generation. Independent Windows clock
  observations bracket the renderer result. A failed observation consumes its
  attempt but leaves normal finish available.

The coordinator retains original generation handles and checks their session,
methods, capture, journal and retirement state. Copied receipts and restarted
coordinators cannot adopt them. Clock artifacts use a deterministic separate
directory, preserving the existing baseline's exact 24-phase evidence layout.
Neither action arms a timestamp window, performs a CAD mutation or adds Save.
The control skill documents the ordering, refusal handling and remaining limits.
Original replies are retained before follow-up clock or owner checks can fail.
After restart, public inspection reports bounded sidecar descriptors without
reconstructing original authority or allowing another attempt.

The scratch compiler runs the complete current offset scan before returning
the generic helper's existing clock-control result. That wire result does not
retain the full scan payload: `fullScanWireOutputRetained:false` is explicit.
No historical APP-source authority is reused. The loaded-project renderer uses
the existing exact project-only guard, rather than the historical Start Page
URL condition. Historical programs and protocol schemas are unchanged.

`freshClockObservationForClosedCapture` forwards an original retained capture
through its original validator. It requires the same authenticated session and
an active dispatch lease, checks the result's operation/capture/runtime binding,
and does not allocate another capture or probe the runtime after sampling.

The private `current-symbol-write-program.ts` compiler implements one fixed
project-qualified name/non-null-description patch. It checks exact before-state,
project, permission, UI actors, client and ticket, then takes a document-clock
sample and repeats the before-state checks. It refuses observed backward time
or either expired immutable 60-second window immediately before dispatch.
There is no await between the final deadline check and the sole mutation.
Independent readback and a second document-clock sample check the result.
Timeouts cannot continue into a late mutation after an awaited read settles.
The complete result and outer JSON envelope are conservatively sized before
code generation, including escaping and multibyte strings. Oversized metadata
therefore refuses before any RPC rather than failing only after a write.

This compiler is not registered or called by a live tool. It does not claim
atomic compare-and-swap, internal worker identity, backend actor identity,
cross-invocation receiver continuity, persistence or execution authority.
Retaining the outer RPC bus cannot lock the manager's internal worker selection.
The future coordinator must issue provenance for the original dispatch and raw
clock samples; caller-supplied comparisons are not enough.

## Verification and release

Focused synthetic tests cover original-generation ownership, one-shot failure
handling, unchanged baseline evidence, clock transport and the fixed writer.
The compiler/registration run passed 11 cases; generation/lifecycle checks
passed 12 plus one owner-loss inspection case; issuer checks passed eight.
The closed-capture clock and related regression run passed 76, including
18 new cases. Whole-project typechecking, strict type-aware lint with zero
warnings, build, compatibility, coverage, package/repository and all seven
official skill validators passed. Dependency signatures and security audits
are clean. No duplicate full local matrix was run. GitHub CI and installation
results are recorded in the engineering checkpoint and PR receipt after they
actually complete.

No live EasyEDA call, project edit, Save or restoration was made for this
implementation. The previously completed disposable lifecycle remains terminal
and must not be replayed merely to recreate evidence. Production designs and
their project records are outside scope.
