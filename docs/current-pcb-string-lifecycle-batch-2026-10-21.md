lifecycle components. It does not register String create, Save or clock actions
in the public validation tool, and it does not establish connected writer

## Dormant lifecycle and provenance

The new lifecycle ledger requires original create plans, actor/SQL provenance
and completed SQL-reader results. It exclusively reserves its operation
directory and consumes each create or Save attempt before returning a durable
hash-linked reservation. Missing, malformed or ambiguous results do not permit replay.
Each step checks the original journal directory, exact record roster and bytes.
Copied tokens and another ledger's tokens cannot advance it.

The ledger composes the existing post-create/publication, whole-SQL and reopened
String comparators, then a distinct final whole-SQL comparison. Its terminal
state is explicitly `comparisons-complete-awaiting-native-lifecycle-proof`.
Supplied replies stay supplied: the ledger has no transport, original native
dispatch proof, verified generation closure, fresh reopen owner or visual
acceptance. A future coordinator must also block unresolved operations globally;
choosing a fresh operation ID must not bypass an ambiguous previous attempt.

String Save-provenance binds an original actor packet to the original completed
SQL inventory. Exact worker-user JSON and backend actor candidates are retained
without converting matching names into backend producer authority. The private
Windows clock issuer binds one-shot before/armed/post/termination observations
to the original helper, root and Job. Termination requires an actual original
termination observation. It cannot reuse rename-clock tokens or historical JSON.
Neither component establishes future Save timing or dispatch eligibility.
The dormant Save-clock composition seals original live pre/post values before
termination and then checks only the original terminal token's current owner.
Its timestamp windows remain conditional on the reviewed Date/VFS behavior and
no intervening OS-clock change; matching supplied history is not proof of Save.

The fixed server-time RPC program and wire adapter remain dormant. Their replies
are captured as bounded immutable own data before post-await owner checks. No
RPC is registered merely because its decoder and transport adapter exist:
durable dispatch intent, original routing and destination containment are still
required. Clock observations do not authorize create or Save.
