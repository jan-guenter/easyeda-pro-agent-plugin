# Current PCB identities and historical recovery

Candidate: `0.3.0+codex.20261014054500`. This is a scoped backlog release,
not completion of every EasyEDA API family. Publication and installation
receipts belong on the originating PR after exact-head CI passes.

## Implemented

- Five current-version native equivalents: selected primitive IDs, unfiltered
  Line/Arc/Via IDs, and positive type lookup within those three families.
  Each binds the ordinary active PCB frame, receiver and exact target across
  two ordered matching observations. IDs describe loaded views, not complete
  saved records, inherited ownership, geometry or connectivity.
- Local-only `history` tool exposing the existing sixteen-event pre-navigation
  validation abandonment verifier. Exact request and confirmation, unchanged
  helper and shared serialized gate. Qualification preserves the original
  journal and permanent claim; it grants no process, completion or replay
  authority. It does not expose the broader legacy recovery tool.
- Context metadata now admits32/64-hex project IDs, including installed local
  path hashes. Branches remain32 and document IDs16/32; exact tab, current
  project and tab PID equality remain required.
- Offline schemas, argument validation, five coverage routes, packaged skill
  instructions and exact tool contracts updated together:39 legacy tools,
  14 restricted tools, unchanged three-tool offline fallback.

The [research note](2026-10-14-current-pcb-readers-research.md) records official
sources, pinned implementation traces and the narrower native semantics.
Adapter output is limited to393216 UTF-8 bytes, leaving room under the facade's
512KiB response limit. It also limits each family to20,000 IDs, selection to256,
and each ID to256 characters. Exceeding either count or byte bounds refuses
without truncation; no paging or vendor cancellation is implied.

## Verification and remaining work

Focused checks cover cross-realm native receiver execution, ordered/empty IDs,
malformed/duplicate/ambiguous/missing identities, target drift, exact local
project identity, historical wrapper refusal and actual registration wiring.
Release checks retain strict types, zero-warning lint, reproducible build,
inventory/package/skill validators and required GitHub CI. Actual final
results and commit IDs will be recorded in AGENTS.md and the PR delivery receipt.

Next connected step is supported historical abandonment on a fresh installed
host, followed by normal disposable startup/opening and these read-only
observations. Do not replay the old validation, manually edit its journal,
relax the shared blocker or hotpatch the running host.

Concrete omissions for this slice:

- Current active-layer lookup: the public body is empty. Native flags can
  mirror layer12 to47 and disagree with the canonical model during reload;
  filtering flags does not implement the method. A bounded canonical witness
  remains needed.
- Component/Pad IDs: getter serialization reaches more caches, attributes,
  pad shapes or rule projections. Their complete effect traces are not yet
  reviewed. These methods are feasible backlog, not claimed impossible.
- Filters, full selected objects and geometry: outside this ID-only contract;
  lossy public/native selected-object projections cannot establish completeness.
- Six-event baseline and later-phase recovery: the new local tool admits only
  the existing sixteen-event verifier. Baseline recovery has a separate
  retained-entry reservation contract; later phases need their own proof.
- Design writers: native structure-job completion and complete SQL-effect
  proof remain missing for the blocked schematic/symbol/PCB families.
  Broader lifecycle, exports, account/library and native-dialog work stays in
  the [scoped backlog](2026-10-13-scoped-release.md) and per-method inventory.

No bridge extension or external compatibility pin changed. Installed source
review, offline tests, connected observation and saved-design verification
remain separate claims.
