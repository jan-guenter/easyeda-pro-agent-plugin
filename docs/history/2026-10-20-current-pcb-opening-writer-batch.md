## Implemented batch

### Opening events

A source-reviewed root tracker admits only the fixed project/PCB fragment
destinations. It balances renderer scheduled/cleared navigation, retains exact
fragment/history observations, and treats browser loading/start messages as
bounded advisory observations. A pending start loader never replaces the
committed root loader. A late browser start for the already sealed project URL
may cross into PCB opening; old renderer scheduling/commit events cannot.

A separate child tracker admits one optional initial blank commit and one
distinct PCB commit for the exact newly attached iframe. Optional initial-frame
scheduling and delayed browser starts are handled without asserting a total
order across browser and renderer producers. A delayed blank start must match
an actually retained blank commit and loader. Foreign identities, replacement
loaders, repeats and unknown transitions still refuse.

Initial child-context destruction requires its exact numeric and unique
identity. Its allowance is cleared at PCB commit, including when Chromium
reuses a same-origin initial context. Existing full target, frame, committed
loader, UI/PCB source, DOM and process checks remain.

The bounded failure label roster now includes additional known Page, Runtime
and Debugger events. A label does not make an event acceptable; event payloads
and URLs are not copied into these diagnostics.

See [the Chromium source audit](2026-10-20-current-pcb-cdp-navigation-audit.md).
Synthetic acceptance is not connected qualification of this path.

### String composition

`current-pcb-string-empty-baseline.ts` composes four existing strict diagnostic
decoders into 47 named conditions. It checks document identity, duplicate
String/copper observations and required manager presence. Missing state remains
unmet. All authority flags remain false.

`current-pcb-string-postcreate.ts` joins the original candidate, original create
observation plan, publication plan and acknowledged native ID with exact empty
