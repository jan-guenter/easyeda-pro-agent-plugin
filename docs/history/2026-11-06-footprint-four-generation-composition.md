The immediate source defect was narrower: the original forward-v2 main request
and completion collectors already had distinct origin factories, but the paired
scheduler accepted only a Combined capability. The new
`CurrentFootprintForwardExecutionPairedScheduler` has its own class and
`private.current-footprint-forward-paired-observation.v2` packet. The old
Combined scheduler, constructor and v1 packet remain unchanged.

Its constructor requires the actual v2 request origin and a genuine late-body
reservation for the exact copy plan retained by the original settled v2 source.
Another valid plan/reservation, copied capability or copied origin refuses
before main arming. Main must arm before clock binding. Binding requires the
clock registry to name the very same original forward-v2 owner/main runner and
an original allocated-destination collector; a known UUID cannot replace it.
The fixed sequence retains the original pending create, collects and retires
both original clocks before collecting main completion, then joins only the
same original create reply. It checks that the exact allocated copy/window was
qualified before dispatch. Native birth, head/frontier and whole-transaction
eligibility remain separate; this scheduler issues none of them.

Cleanup retains the same original route, allocation, clock and main collectors.
A pending operation remains joined before post-exit cleanup; no replacement
request, reconstructed handle or JSON packet can settle it. Its new packet
preserves false full-qualification, native-SQL, saved-result and execution flags.
The original forward/Combined request ceilings are unchanged: this increment
composes existing sequencers and adds no native command or helper codebook.

Focused verification used pinned Node 24.18.0 with the maintained isolation
preload and core limit zero. Nine main/capability/paired checks pass; after a
final type-only import consolidation, both new paired cases pass again. The
positive case uses the actual private factory/main/capability/origin classes,
real managed publication and a complete synthetic SQL copy plan, with explicit
synthetic installation/source/inspector/helper seams. It arms the original main
once and refuses a foreign clock before dispatch. It does not prove successful
native allocated-clock binding, a create, complete SQL mutation, reopen or
inverse. Full types and strict changed-file type-aware lint pass.

The next implementation boundary is a distinct cold-v2 allocated-clock issuer:
retain the exact original source/opening, construction/invocation leases,
registration and cold continuation, then expose it only through the new genuine
writer composition. Current source/head/producer and all-four-generation gates
must remain closed until their original proofs and actual schedules exist.
