# Closed generated data index mount

The new `easyeda_control_fixture_data` tool mounts the separate closed-data
coordinator from development commit `cd65a8a6`. It requires a fresh facade with
no other allocated or staged workflow. A newly constructed never-launched209
proof runtime belongs only to this coordinator, with current executable/helper
and facade-scope pins. It is never assigned to the ordinary application runtime.
All coordinator methods are captured and checked against their original
prototype before use.

The first request selects managed archive/capture digests. Subsequent inspection,
record settlement and confirmed release use that same coordinator. PCB and SCH
staging happen locally after resource/record release. Only the corresponding
opaque data token enters the existing independent reader slot, before a new
ordinary launch. The new route accepts no old process or ownership receipt,
target object, path, source code or custom qualification profile.

An active data reservation blocks other guarded callbacks and retirement.
The original serialized gate also rechecks this reservation when queued work
actually enters. This prevents a callback queued before qualification from
starting a competing workflow after qualification fails or retains resources.
Only the original data route and local API/session inspection bypass that
callback refusal. Retirement still requires actual resource and journal release.
The separately registered closed-symbol entry refuses before reserving any
runtime. Constructor setup is synchronous and acquires no file/helper; no
native allocation is discarded after an asynchronous attempt.

Offline schema/query/validation, source tool contracts, mode registration and
capability metadata include this route. It remains a read-only native-data
workflow with local journals/artifacts, rather than a design writer or public
SDK call. Its separate Windows helper still requires Windows5.1 compile-only
verification and a connected disposable case before native reuse acceptance.

Pinned source types and strict type-aware lint pass for the mount. Two focused
regressions execute the actual index gate function with the production
`SerializedGate`: an already-queued competing callback stays unentered, the
original data callback can settle, and an altered custody observer fails closed.
These do not qualify the native helper. Combined bundles, catalog/contract
validation and exact final CI remain part of the larger unpublished batch.
