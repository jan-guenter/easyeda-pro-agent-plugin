its startup scheduler first refuses a source-qualified SQL pause. The site and
scheduler refusal category are stored before any diagnostic await. At most two
existing readonly commands capture the fixed site tuple and its own property
descriptors. The summary reports only operand kinds, a closed path category and
a closed SQL category. It contains no raw SQL, paths, parameters or handles.

The original `SELECTED_SQL_UNQUALIFIED_STARTUP_MUTATION` and its pre-diagnostic
phase survive refused frame reads, malformed metadata and later observation
attempts. No SQL call is resumed, no configuration or clock is invoked, and the
existing public `retained()` and Main failure v1 shapes are unchanged. The new
private getter and strict data schema provide the seam for a separate artifact
owned by the original workflow/coordinator. Persistence wiring is a separate
integration prerequisite before a connected diagnostic attempt.

The prior connected failure identifies neither its first site nor the cause of
the breakpoint predicate. This change does not claim a missing startup chain,
a diagnosed application defect, a safe mutation or successful writer execution.

## Same-owner private persistence

native owner's captured prototype method. It independently checks that method,
copies the closed data through the descriptor-safe reply boundary and freezes
the strictly validated result. A substituted getter or malformed packet is
omitted without invoking its accessors, replacing the original failure or
blocking original process and helper cleanup.

`evidence.mainStartupDiagnostic` in the original private failure phase artifact.
