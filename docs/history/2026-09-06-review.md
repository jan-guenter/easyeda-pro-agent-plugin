# Follow-up engineering review, 2026-09-06

Scope: the released plugin at `4b5acbf`, its MCP startup path, filesystem evidence and checkpoints, TypeScript/lint coverage, dependency audit, packaging, and skill behavior. Review used independent runtime, evidence, and tooling passes plus integration review. No production design edits or writer enablement were authorized or performed.

## Findings and changes

| Finding | Change and regression evidence |
|---|---|
| The real upstream could not start inside its network policy. The reviewed `ws` server passes a `null` backlog and Node normalizes it to zero; both were rejected. Fake-upstream tests missed this. | Admit only these default-backlog representations while retaining exact loopback address/port, no inherited listener descriptor, and restricted flags. Exercise the real `ws` server plus alternate address/port/descriptor rejection. |
| Startup errors hid their phase together with private stderr. | Return a fixed startup-stage enum and observed monitor/sandbox exit values. Private stderr and nested causes remain withheld. These values localize failure; cleanup exits are not automatically its root cause. |
| A second caller during startup could see an incomplete-cleanup error after the gateway had been published. | Join the existing startup promise before testing retained generation state. Regression recreates the published-gateway window. |
| The OS-selected backend port could equal the fixed public gateway port and cause a self-collision. | Exclude the configured gateway port, close every rejected reservation, and stop after eight OS-assigned attempts. Deterministic tests cover retry, exhaustion, malformed address, default exclusion, and invalid input without opening sockets. |
| Child exit could win a race against opening its executable, abandoning a late FileHandle. | Finish descriptor acquisition before observing closure, then close it through the existing cleanup path. Regression proves the handle is closed. |
| Checkpoint source changes could escape the final creation/verification result. A checkpoint could also change after hashing. | Recheck descriptor/path identity, stable file metadata, and connection-local SQLite data version after the final awaited work. Tests cover DELETE/WAL commits, source replacement, and checkpoint mutation. Proof remains point-in-time, not a perpetual lock on the live database. |
| Internally contradictory evidence receipts could verify despite mismatched request, schema, metadata, or attachment lists. | Validate field types and require exact receipt/result agreement before artifact checks. Unkeyed hashes still detect corruption, not a same-user adversary who can rewrite both code and evidence. |
| Whole-file JSON reads were unbounded; binary verification could follow file growth. | Limit managed JSON read/publication to 64 MiB, checkpoint receipts to 1 MiB, and stream binary hashes over the admitted size with post-read checks. Sparse-file regressions reject before large allocation. |
| Caller-selected evidence output could occupy the operation-journal directory and trigger global quarantine. | Reserve that directory for journal APIs; reject evidence publication there before creating files. Local artifact inspection remains permitted. |
| Local discovery could start a broken upstream, and upstream annotations did not explain facade availability. | Default to local/read discovery. Explicit live mode provides current schemas. Results state their source, schema availability, and admitted facade route or `unavailable`; live metadata drift cannot advertise a rejected generic-read route. |
| The root release validator was outside TypeScript and type-aware lint. Its strict-config checks accepted false values when keys existed. | Migrate it into the plugin's strict project, schema-parse metadata, check exact compiler-option values, reject ambiguous repository paths, and add behavioral tests. Three frozen fail-closed upstream `.mjs` stubs now have strict `checkJs` coverage without changing the private bridge source closure. |
| The locked `qs` version gained two moderate advisories after the previous release; the high-only CI gate passed them. | Update only `qs` from 6.15.3 to 6.16.0, verify signatures and audit again, and reject moderate findings in CI. Disable dependency install hooks while preserving explicit reviewed project scripts. |
| The skill repeated enforced implementation details and mixed startup failures with authenticated compatibility validation. | Shorten the entrypoint, route setup and implementation details to references, distinguish host/startup/session/admission failures, and clarify the bounded candidate-validation exception. Independent scenario testing caught and corrected a contradictory full-admission instruction. |

The dependency advisories are [bracket-key array-limit bypass](https://github.com/advisories/GHSA-x5fp-wj9c-mxmx) and [attacker-controlled isBuffer denial of service](https://github.com/advisories/GHSA-4mjr-xmp4-gh2g).
