# Original record to held AST entry

The original own7 callback now supports the next bounded continuation through
`prepareOriginalRecord()`, `continueOriginalRecordToAst()` and
`observeOriginalAstHeld()`. It requires the exact original primitive record
receipt, publisher pristine receipt and completed normal-history graph.

At the held record entry, seven fixed reads prove the same original event and
model, the own connected flag and the actual lexical `t` function's JavaScript
identity against the previously qualified original AST closure. Exact raw,
publisher and normal-history snapshots still allow only the earlier planned
underline transition. No other descriptor, prototype or peer may change.

The record body first checks that connected flag, then calls `t()` synchronously.
The AST function-call breakpoint was armed before the original action. One
reserved/submitted continuation therefore reaches that original AST entry and
holds before `shouldUpdateAst` or any later monitor is changed. Both the original
write acknowledgement and Debugger.resumed are joined; the AST pause can arrive
before or after acknowledgement. No retry or inferred completion is allowed.

Seven further reads prove the actual AST lexical receiver and unchanged exact
partial state. The receipt keeps the AST body held, further writes unauthorized,
and Modify/Save incomplete. The separate native grammar has one resume and
exact seven-read ordinals on either side plus three controls, eighteen reserved
requests total. It has no AST-body or monitor/publication resume row. Existing
six-record, Wire and Via purposes cannot use it.

Actual Node24 Inspector regressions preserve both pinned complete monitor/watch
class bodies. At the AST entry, the receiver is the original monitor, underline
is already changed, the AST flag is still false and all later monitor counts
remain zero. Pure checks cover wrong lexical function, disconnected/replaced
models and accessor replacement without invoking a hook. Original-event ordering,
foreign codecs, fixed expressions and the pending Modify pipe are also checked.
The existing complete native-source generation remains idempotent and bounded.
No EasyEDA, native helper, MCP transport or installed payload was used.
