# Maintained fresh CLI metadata proof helper

The private installed-snapshot workflow proved fresh Linux and Windows CLI
registries against merged `ced687c65e262859a95ee7e36c2c9374dd7d846c` without a
Codex restart. The successful actual Linux/Windows metadata cases, prior routing
and observer failures, full raw replies, original pidfd/handle exits and limits
remain in the [installed handoff record](2026-11-15-installed-fresh-cli-handoff.md).
Those observations are not repeated or relabeled as acceptance of this refactor.

Three builtin-only TypeScript modules now maintain that sequence: strict immutable
plan/default preview and fixed coordinator; preallocated evidence/control and
original process resources; fixed Linux/Windows watcher programs. The package
entry and control reference explain trusted local preparation, complete disabled
unrelated sources, empty workspace outside projects, explicit portable distro/
Windows Node inputs, full Linux V2/Windows byte prerequisites and exact scope.

The helper uses Codex CLI 0.168's threadId+serverName connection route and bare tool
names, exact plugin ID, bounded status pagination/repeated-cursor refusal, and
only loaded-facade/inspect/retire/close-retired. No model turn, ordinary Status,
bridge/native/project execution, arbitrary RPC, global config/auth mutation or
cache patch is added. No facade tool or runtime/profile admission is broadened.
Retirement also requires liveAdmissionOpen:false; scheduled-close metadata is
never mistaken for an observed original exit.

All local descriptors are allocated before a CLI can spawn. Partial initializer
failure closes those original descriptors. Partial journal writes retain their
exact unwritten suffix; disk-full errors stop normal dispatch but cannot throw
before original stdin EOF and watcher settlement. Bounded unknown bytes remain
retained until original journal flush, while failures stay incomplete. Received
stream hashes are labeled separately from current disk bytes. Fixed nonce-bound
status/EOF/watcher controls remain available without exposing arbitrary RPC.
A terminal cleanup manifest records only the original-created closed workspace;
the helper creates no full runtime copies/clones and offers no generic purge.

Focused inert checks cover default preview with no owner, strict plan/object-hook
refusal, partial evidence initialization before any CLI allocation, and simulated
ENOSPC preserving raw bytes plus actual original inert-child EOF/close 0.
Fatal UTF-8 chunk/final-EOF validation rejects malformed ignored fields and a
valid record followed by an incomplete multibyte sequence despite physical exit 0.
Intentional EOF revokes dispatch separately; final success checks every original
peer protocol-health snapshot after all EOF flushes. These checks
start no real Codex app-server, EasyEDA facade, upstream, application or native
owner. Both facade TypeScript projects pass, as do four focused inert tests
with zero skips, strict type-aware lint on all four new source/test files,
repository and isolated catalog contracts, and all seven skill validations.
Maintained default-preview commands also pass on Linux Node 24.18.0 and Windows
Node 24.10.0 without owner allocation. The unchanged dependency lock reuses the
preceding real npm ci, signature/attestation and zero-vulnerability audit receipts.
Outgoing history privacy is checked before handoff. Combined release build/source

A bounded frozen-source review then identified two P2 gaps before publication.
The original coordinator inspected before acquiring the serving facade's pidfd;
an early inspect/capture failure could confuse closed transports with serving
process exit. The watcher now acquires and reports original pidfd custody directly
after loaded-facade, before inspect. Post-capture failure retains that same pidfd
through its actual exit. Failed initial capture leaves an explicit unresolved
facade exit, and the terminal manifest cannot claim all originals closed or allow
workspace cleanup from CLI/watcher transport closure alone.

The first journal refactor wrote and closed descriptors without file/parent
directory sync. Linux now retains original no-follow directory FDs and syncs all
exclusive journal/control files, created directories and their existing parents
before any owner allocation. Later flushes retain pending unsynced state on a
failed original file or directory sync, revoke normal dispatch, preserve EOF and
join original transports/watchers before incomplete settlement. Descriptor-close
failure remains incomplete; it cannot become a positive proof.

Windows preview still starts no owner. Windows --prove now refuses BEFORE owner,
workspace or evidence allocation: no supported unprivileged directory durability
primitive was established for that route. File flush and DrvFS success are not
claimed as NTFS namespace durability, and no volume flush or disk/global setting
change is attempted. Earlier Windows metadata/handle observations retain their
bounded storage scope and are not acceptance of this new durable helper. A fixed
Linux evidence broker for a Windows driver is future work; Linux fresh CLI and
maintained-manager routes remain available without a Codex desktop restart.

Two additional focused inert cases cover original pidfd-before-inspect error,
failed initial capture preserving unknown exit despite transport close 0, initial
directory-sync refusal, and post-allocation file-sync failure retaining original
EOF/close and pending sync state. These use fake CLI packets and an inert Node
stdin child, never a real app-server, facade, upstream or native owner. Final
checks for this correction: six focused tests pass with zero skips; both facade
TypeScript projects pass; strict type-aware lint on the four affected source/test
files reports zero warnings/errors; all seven skill validations pass. No additional
whole-suite, runtime admission or Windows native probe was run. Outgoing privacy
is checked before handoff; the combined release build remains the parent
release coordinator's work.
