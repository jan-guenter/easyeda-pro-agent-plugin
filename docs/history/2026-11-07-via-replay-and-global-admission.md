The private Via workflow is still under implementation and has no public MCP
entry. This continuation adds two prerequisites for mounting it safely.

The readonly pre-replay program rechecks the same original Save entry and body,
including the actual consistency-manager map, document, link and last node.
The node must still be unpended, with the original ticket, client and data.
The incoming delta must contain the exact DOCHEAD/VIA pair, without a pending
or foreign-client Via header. Four parser/consistency-manager method bodies are
pinned to the inspected current209 source. Under that original existing-node
branch, the Via does not call `publishChange`. This does not prove an arbitrary
history emits no callbacks. The actual held sync frame, incoming cache data and
native continuation still require their own original-owner joins.

The original Main live-history observer now has separate arm and row joins in
the writer coordinator. Its arm must complete before the actual history GET is
released. The fresh per-request database-connection correction and private cache
projection are recorded in the [live cache plan](2026-11-07-via-live-cache-plan.md).

Global admission now recognizes the reserved Via operation ID and both private
journal versions before the generic completed-journal shortcut. Every unfinished
or invalid Via journal quarantines bridge dispatch and native startup, including
when the generic orphan flag is absent or false. A claimed terminal state must
pass the private chain, plan/phase identity, all exact managed phase files and a
fresh final journal read. Historical acceptance grants no owner, continuation,
replay or new native allocation. Failed allocated workflows remain unresolved
after resource cleanup; closing an app cannot establish a successful Save.

Validation uses isolated V8 programs and actual managed synthetic journals.
Seven focused Save-program cases and four admission cases passed. Changed
strict type-aware lint has no warnings. No application or native owner was
created by these checks. The outer writer draft still awaits the actual upload
drain before it can compile and be mounted. No helper pin, bundle, release,
installation or connected writer support is claimed here. excluded production design remains
