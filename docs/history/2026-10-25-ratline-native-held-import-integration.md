# Ratline native held-import integration

## Scope

This batch connects the private PCB/source/child components from
[the preceding release](2026-10-25-native-startup-and-ownership-diagnostics.md)
to a distinct original native launch purpose. The `ratline-held-import` wrapper
of `easyeda_control_pcb209_worker_startup` uses `pcb209-ratline-*` operations.
After original project capture, it journals intent before PCB navigation,
qualifies 29 PCB source phases, observes PCB construction and qualifies seven
source phases in the first child, leaving its final import held.

This is a partial diagnostic. It does not independently associate the JavaScript
Worker object with its CDP target, continue the worker import, capture a
subordinate worker, prove callback return or publication completion, establish
a complete live baseline, or authorize editing or Save. The public packet keeps
those claims false. Source qualification and native frame ancestry are distinct
from Worker-target identity.

## Implementation

The original native process, Job, debugger pipes and source leases remain owned
through cleanup. The fixed installation plan retains 17 files, including the
complete deduplicated source dependency set and the original five core files.
The parent context router handles existing-context replay and the PCB context
transition, then performs three target/frame/DOM proof sets. It transfers the
parent event stream once; the original project-worker subscriber remains bound
to its own sessions.

One ledger begins before helper spawn and accounts for discovery, project
capture, source loading and construction. It allows 315 normal CDP requests
plus 43 reserved cleanup requests, with per-request reply limits, ordered source
slots and separate normal/cleanup byte, poll and control allowances. Normal
work has a 60-minute launch limit with a 60-second cleanup reserve. Individual
source deadlines derive from exact source sizes and bounded chunk drains;
ordinary acknowledgments retain their 2.5-second limit. These are availability
limits, not throughput or completion guarantees.

The native helper stays below its existing 1 MiB source bound. Packed fixed
protocol metadata replaces repeated literals; exhaustive parity vectors remain
in the compiled test fixture. The original startup runtime encoder is unchanged.
The new purpose rejects child continuation after its seventh source phase and
also rejects attempts to resume that child through the older startup vocabulary.
Original termination ends pending allocation retention without reconstructing
ownership or treating a timeout as exit.

Cleanup is one-way and retains its original promise. It applies even when a
session was prepared but capture never began. The lifecycle aborts before normal
close and releases the original session before the project-opening and native
owners. Malformed pipe evidence remains a refusal. Failed or unqualified child
pauses receive no continuation authority.
