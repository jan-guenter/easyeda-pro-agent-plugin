# Selected SQLite installation leases

[CodeRabbit comment4504119979](https://github.com/jan-guenter/easyeda-pro-agent-plugin/pull/174#discussion_r4504119979)
correctly identified an import interval gap. Descriptor hashing before launch
and runtime inspection after `require("sqlite3")` did not retain the imported
module bytes through that import.

The selected-file SQL purposes now use a fixed13-file native installation plan.
It preserves the original five core slots and appends the deduplicated reviewed
SQLite package, entry module, implementation, binding loader, native binding,
C++ source pins and the exact SDK module. The ordinary diagnostic five-file and
ratline17-file plans keep their existing scopes and order. The eager installed
SQLite import uses only these pinned files and Node builtins. Its lazy verbose
trace module is not invoked by the qualified application import.

The native validator checks the complete fixed path, length and hash roster
before admission. The existing installation owner then acquires and hashes every
extra file and its ancestors through the same retained Windows handles. Its
`CreateFile` sharing mode permits reads and denies writes and deletion.
All these acquisitions and fresh identity checks finish before
`CreateVerifiedRoot()`. The original installation retains them through original
process and Job closure. A metadata read alone is still not a file lease.

Only the fixed selected-SQL birth flags select the extended roster. The native
getter has no setter or caller input. PowerShell derives its expected file
count from that same original owner. The Core factory selects matching fixed
installation and facade verifiers. Existing owner, source, context and runtime
checks remain in force; no hash, lease, compiler or request limit increased.

Four focused plan/native-order cases passed, both TypeScript configurations
passed, and final changed strict lint had zero warnings. All three native
layouts generate byte-exactly on their second pass. Their exact C#5 compiler
inputs also compiled and ran available Via clock, SDK boundary and dual-cache
slot smokes under Linux .NET, without creating an application or native owner.
This compilation is separate from a Windows retained-file effect test.

Measured compiler inputs were1,865,158 bytes for diagnostic,2,057,712 for
schematic and2,093,791 for inverse. Every input remains below the unchanged
2 MiB cap. The inverse's3,361-byte margin requires a reviewed code projection
before adding its next result observer.

The first generation attempt changed birth constructors inside a separately
exact saved-reader region. Its second pass correctly refused that modified
region. The correction derives the readonly native getter from the original
birth flags and leaves those generated regions byte-exact. The original failure
and corrected results remain in private evidence. No tracked helper, pin or
bundle has been regenerated in this source commit. The next private build must
include these changes before a connected writer is selected.

The subsequent integration retained the new schematic status lane and all
existing inverse/saved-reader lanes. Its32 focused original-owner/status cases,
both TypeScript configurations and changed strict lint passed. The historical
ratline fixture now expects its exact branch inside the new selected-SQL file
count dispatch. This assertion must be run against the regenerated helper in
