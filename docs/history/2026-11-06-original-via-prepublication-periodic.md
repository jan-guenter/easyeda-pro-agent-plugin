# Original Via prepublication same-head periodic continuation

The producer observer has distinct continuePreSavePeriodicSyncCall(packet) and
settlePreSavePeriodicSyncCall() methods. They use the same original periodic
cursor, immutable branch/history plan, native table and aggregate 32-call
reservation as startup. The methods require the original consumed create
intent and Main pre-create enrollment. No new caller origin, expected row,
program, timer, SQL grant or duplicate request budget is accepted.

A startup call that already entered may retain its exact scope while create
is consumed. New admissions through the old startup API afterward refuse.
The dedicated prepublication scope checks the same genuine enrollment around
all awaits. Metadata-only settlement may preserve that observer's own exact
held marker, without resuming or replacing it.

The immutable programs are unchanged: complete original branch and history
rows must match before the original branch-head/property read and merge; the
merged result must have m=false and d=0 with the same docs/editHead/docIds.
Changed heads, unsafe data, upload/deferred branches or unknown callers remain
held. The native Via predicate permits the enrolled original create boundary
without requiring SDK ACK/effect (which could itself await the worker), and
stops once the native history transaction advances. Request generation may
already be pending; it does not become publication authority. The old schematic
startup policy and all released purposes are unchanged.

The actual source-only sync function executes on an inert complete initial
head with an independent pending Via record and preserves it by identity,
without model parsing, native Cache effects or getters. Thirteen focused
periodic/collector cases, both TypeScript projects and changed strict lint
pass. Private two-pass generation and Linux full C#/fixed codec smokes pass;
helper size 1,883,543 bytes (+239), SHA256
e23992b753e0c6f65a30aec156312965c4df8047d5b39063de47be076c43430c.
Command bytes, 26 shapes, per-call ceilings and the aggregate 32 bound remain
unchanged. No tracked helper/pin, Windows, application or native-owner call ran.

requireViaLiveHistoryBody(plan) is a separate data-only live lookup for the
next post-history cache projection. It returns the exact private delta,
worker value and clock only after the original completed Main/native history
ledger agrees on body SHA and ticket. It grants no worker or SQL continuation.

This removes an admission deadlock but does not establish a complete uploader
frontier or quiet event stream. Overdue periodic reads can still overlap later
uploader awaits; every real event retains its original observer. The deliberate
first-timer cancellation under separate pre-navigation journal intent is being
implemented as a different session action, preserving these readonly APIs.
