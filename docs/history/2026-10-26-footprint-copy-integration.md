## Implemented scope

The separate `footprint-copy-preparation` launch purpose connects retained
source preparation, direct producer bindings and actor/SQL preparation to the
original startup lifecycle and durable journal. Its public requests have a
distinct operation prefix and cannot upgrade an existing startup owner.
Original startup request and state-sample limits remain unchanged.

The UI collector qualifies the notification wrapper, responder, initialized
extension registry and bus on the original parent. It retains raw replies,
rejects changed methods or scopes and rechecks registry membership. Parent
frame checks and worker identity checks bracket the observation. Matching
identity values do not establish the bus's actual worker destination.

The transaction clock collector separately captures the native `buildString`
and `canvasString` post-await values. It never calls `qe` as a preliminary
probe. Distinct calls can return the same number. The collector retains
breakpoint and pause evidence, consumes dispatch once and records uncertainty
after possible mutation. It has no writer route or embedded-V8 validation yet.

The new preparation channel reserves cleanup requests and a cleanup interval.
Review found that an unconditional normal deadline initially blocked that
interval; it was corrected to permit cleanup and polling until the total
deadline. The native helper's original Stopwatch also bounds polling. Unknown
caller objects are rejected before choosing a command grammar, avoiding proxy
or prototype traps.

The mounted dependency stage qualifies 53 helper, serializer, parser, cache,
upload and notification functions without invoking them or creating a bus.
The manager reader follows the original UI subscription through its initialized
registry to the project and worker bus. It reads and qualifies the original
callback's manager script before following its scope. Reciprocal worker/bus
identity, dynamic backend dispatch and asynchronous completion remain unproved.

The preparation profile admits 553 normal requests, 34 cleanup requests and 18
state samples, with an hour for work and a separate minute for cleanup. The
64MiB cumulative byte cap is unchanged and can refuse before the request cap.
The two new group-release slots reserve internal owner capacity; the public
lifecycle uses original process closure and proven root/Job termination to
end these groups. No new remote-release action was added.
A review caught and corrected an unsupported increase to 21 state samples:
the manager stage adds requests but no state samples. No copy or Save authority
follows from these observations.

## Review corrections

The manager bus UUID is random, not the native channel name. The reader now
checks the initialized cache entry and leaves channel-name and reciprocal-peer
proof explicitly false. It also checks both UI and manager active branches.
The 2,196,424-byte manager script uses a dedicated bounded immutable capture;
its original channel still counts all bytes against the same cumulative cap.
Public inspection returns a digest and byte count, while the original owner
retains full raw replies. This is not a persisted full-observation artifact.

The generated helper shares repeated encoder literals across two independently
bounded compressed tables. All 26 literals are byte-identical and the existing
64KiB decoded-table limit is unchanged. This saves 32,680 source bytes. Final
helper size is 1,020,864 bytes, below the unchanged 1MiB ceiling, SHA256
`782f673c0d7d52cecd67c4c22734af45baf47b114b6656e1ee51c9634eb3ba32`.
A local Windows CompileOnly run initially found a duplicate constructor
signature; the footprint purpose now has its own checked overload. The next
run compiled successfully and proved an empty Job/pipes with no app launched.
