# Initial generated schematic data qualification

The maintained import coordinator accepts the fixed
`fixtureKind:"schematic-text-wire-bus"` scenario from the separate schematic
generator. It uses the same original tracked environment/import Promise,
exclusive destination and retained no-candidate library watches. The destination
helper accepts only the additional fixed `Codex_schematic_<16hex>.eprj2`
basename; its native C# operations and cleanup behavior are unchanged. The helper
source hash changes and must be admitted in the next frozen native generation.

`qualifyGeneratedSchematicFixtureInitialSql` issues a distinct private
`QualifiedGeneratedSchematicFixtureTarget`, containing both `schematicUuid` and
`pageUuid`. It accepts the complete real SCH/SCH_PAGE stream, paired unticked
headers, exact metadata and fixed Text/Wire/Bus/Line bodies, native actor prefix,
and one complete initial history chunk. The schematic parent and each line's
owning Wire or Bus are checked. No PCB document is substituted. The existing PCB
v1 target and result fields stay unchanged, and neither issuer accepts the other
target or a serialized clone.

Complete schema, table, row, default, branch, sequence and encrypted-history
checks moved mechanically into `qualifyGeneratedInitialSqlRows`, which issues no
target. Both fixed source profiles supply their exact expected structure before
that asynchronous comparison. The original completed SQL reader and raw input
archive/path/timestamps remain bound through issuance. Native timestamp handling
and all existing PCB body checks retain their prior behavior.

The exact pinned manager's `Xa` header/META parsers and `Qo`/`hy` projections
produce one keyed `schematics` entry and one keyed `sheets` entry. The sheet uses
`schematic_uuid`; its undefined `docType` is omitted by native JSON serialization.
The schematic name is `META.title`. Header version/updateTime win over the
native EDIT_HEAD fallback. Creator/modifier metadata is intermediate parse data,
and does not enter those structure nodes. Owner remains the original private
destination path plus `/`, with empty username/nickname. The exact main `vB`
method inserts this JSON with ticket1. All other document maps remain empty.

`check-managed-schematic-initial-profile.ts` checks complete manager/main hashes,
six exact UTF16 method ranges and the original main INSERT function. In an
isolated Linux VM it runs the actual header/META and projection methods against
the fixed generated archive. Header/META dispatch and the sheet-order callback
are explicitly supplied; it does not run an importer or schematic editor. Its
output matches the full expected keyed structure. The generator's separate
twelve-method serializer check still covers the primitive source encoding.

After original cleanup, `capture-closed-import` selects the separate schematic
snapshot schema and retains complete SQL, exact decoded history or qualification
failure. It retains a genuine schematic data target only after full initial
qualification. The original coordinator's internal
`stageSchematicSourceForFreshOpening(originalImportOperationId)` requires owner
release, drained migration exclusion and its exact original issued target. Its
separate one-use opaque data token survives only in that facade; it cannot enter
the PCB opener or reconstruct a native owner. A dedicated fresh schematic
registration/page owner remains implementation work. Registration, native page
readiness, electrical connectivity and design execution remain false.

Focused regressions cover the real two-document synthetic initial schema,
complete extra-row/history refusal, wrong structure parent, changed Text bytes,
rewritten page DOCHEAD, archive/path/time mutation during decoding, cross-profile
and cloned-token refusal, and the actual coordinator's tracked scenario dispatch.
These are source and synthetic storage checks, not connected native acceptance.
