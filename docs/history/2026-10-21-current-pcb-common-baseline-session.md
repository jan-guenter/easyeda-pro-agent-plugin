# Original common baseline session

The private `current-pcb-common-baseline-session.ts` composition joins its own
18-command common reader to an original completed SQL inventory. The original
String-purpose lifecycle exposes it as the optional `observe-common-baseline`
stage after worker-source admission and before String precreate. The native route
admits only its fixed programs and original page session. The lifecycle retains
the complete SQL inventory during its one-shot pre-navigation preparation; passing
a checkpoint path or copying inventory JSON cannot replace that completed reader
object. There is no create, edit, FileSource or Save method.

## Sequence and retained evidence

The session consumes its single attempt before asynchronous history work. It first
extracts the exact winning historical DOCHEAD body through the maintained full
history materializer and raw occurrence relation. It checks the existing PCB header
schema without changing the original JSON field order. This is historical data,
not a compiler header or a fabricated current timestamp.

It then constructs its sole `CurrentPcbCommonBaselineRunner`. There is no method to
adopt a caller observation or supply decoded graph objects. After the runner's
original object-group cleanup and final owner check, the session retains the
original observation. The existing five-reply issuance map supplies the exact raw
presentation, rule, preference, asset and metadata text for the stored relation.

The stored join checks every surviving target row, exact common and META bodies,
selected raw history occurrences, target structure, and whole-inventory/peer
commitments. The session compares that join to its separately extracted DOCHEAD
selection. It checks the original owner before and after the asynchronous work
and before returning a frozen packet bounded to 2,121,728 UTF-8 bytes.

A later SQL-join failure preserves the original successful observation and header.
Their presence does not turn the failed session into a success. The original error
and failed phase remain available for private lifecycle evidence. A second call
refuses even if the first failed before dispatch. The sole runner owns its group
cleanup; the session never repeats release, reads or navigation.

The enclosing native owner checks the original target inventory and frame tree
before and after the stage (four additional commands), along with installation,
source, page and worker context identity. Only an exception originating inside the
pure stored-relation call after all five readers and cleanup completed can become
an explicit comparison-refusal result. The session retains that provenance in
private state; an error message, phase label or copied record cannot recreate it.
The final native checks must pass. Header, reader, transport, cleanup and ownership
failures remain fatal to further observations.

A comparison refusal creates no baseline packet and authorizes no retry or writer.
It permits the independent, unchanged precreate stage only after both its failure
record and explicit refusal result are durably published. Both exact publication
plans are retained before publishing either; same-owner settlement may publish
those bytes without rerunning any native command. Pending or mismatched records
block precreate before consuming its attempt.

After a later failure or comparison refusal, the journal retains the original
five raw replies, their hashes, historical header and observation commitment,
bounded to 6 MiB. A successful join keeps raw replies privately in its original
session and publishes summary commitments. MCP inspection returns only a compact
summary with byte counts, hashes and fixed failure labels, preserving the existing
512 KiB response limit. Original constructor-selection failures retain their
branded bundle/profile/stage/reason and the common runner's cleanup outcome; no
arbitrary exception text, remote handles or nested causes enter that summary.

`requireOriginalPacket` accepts only the packet object issued by this session and
rechecks the original lifetime. JSON copies refuse. An observed owner failure
permanently retires packet use while retaining its historical evidence.

## Scope and unsupported cases

The packet proves a comparison of original runner output and original completed
SQL data. It deliberately leaves original native ownership, closed-file ownership,
atomicity, continuous observation, queue completion, complete live geometry and
asset ownership, saved/reopened effects and execution authority false. The enclosing
native lifecycle must establish its own process, source, context, opening and
journal obligations. The session cannot turn an injected assertion callback into
that authority.

The existing empty-target stored subset remains narrow:

- Missing stored common rows are not inferred from native initialized defaults.
- Extra surviving target records, unknown common encodings and incomplete rules
  refuse. Historical tombstones remain in the raw occurrence commitments.
- META is observed independently. DOCHEAD comes from history and is not generated
  from META or the compiler's current clock.
- Non-root parent/source values and unsupported stored header/user shapes refuse.
- A stored structure `zIndex:0` does not silently become the META encoder's null.
- An empty live asset inventory is not proof of complete stored asset ownership.
  The complete SQL and peer commitments remain available for that later work.
- Foreign project/document/branch data, copied completed inventories, copied
  packets, stale owners, failed reader cleanup and conflicting history refuse.

Focused tests use the real runner and retained SQL reader with synthetic renderer
descriptors and isolated encrypted SQLite fixtures. They cover successful joining,
original identity, failed joins with retained raw replies, one-attempt consumption,
owner loss before observation, during cleanup and across SQL joining, hostile
input descriptors and irrevocable lifetime failure. They do not exercise EasyEDA
or qualify a writer. Synthetic lifecycle tests cover optional-stage ordering,
original pre-open inventory identity, explicit refusal versus fatal failure,
failure/result publication uncertainty, exact settlement and subsequent one-shot
precreate. The synthetic native-helper integration checks the real owner path
through all 18 common commands plus four parent reproofs and then independent
precreate; it is not connected execution evidence.
