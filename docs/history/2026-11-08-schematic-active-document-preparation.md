# Passive schematic active-document preparation

The fixed collector prepares the original menu or toolbar callback's
`docManager.isActive` lookup. It retains the actual callback frame, existing
`pe._instance`, document and native Map, selected UI tab bar, source-qualified
functions, and descriptor snapshots. It never calls the application getter,
singleton getter, constructor, manager method, or callback.

The selected path requires the original current tab and a 16- or 32-character
lowercase hexadecimal document key. It excludes the global RegExp branch,
nonstring Map enumeration, and `pureSheets` lookup. Native String split and
includes, Array includes, iterator references, and Map get are joined to the
retained native inputs. String and Object prototype `Symbol.split` and
`Symbol.toStringTag` hooks refuse before those native operations. The complete
window is not enumerated; its identity must equal the retained native root,
and only its own data `UI` binding is read.

Each of ten graph waves has at most twelve prototype levels, with at most
384 qualified values. The finite ceilings are 1,472 collector requests and
816 call/frame helper receipts; the original controller must separately read
each emitted helper's exact source. No breakpoint or resume command exists
in this vocabulary. Every returned continuation, effect, publication, Modify,
and Save flag remains false. The writer must retain and qualify its original
held callback and native inputs before mounting this leaf.

Five focused tests passed with the configured, hash-qualified installed
sources and no skips. These cover all 27 original function metadata profiles,
both actual schematic class paths, passive lookup and zero getter/Proxy trap
counterexamples, and a real Node24 Inspector call with
`throwOnSideEffect:true`. Both TypeScript projects and changed-file strict
lint passed. This is source and inert-program evidence; it does not validate
the live collector, callback continuation, or completed writer lifecycle.
