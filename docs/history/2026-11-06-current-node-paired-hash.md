# Current-process Node descriptor hash reuse

The current-process SQL runtime retains two original descriptors: `/proc/self/exe` and the canonical configured executable. Allocation proves they name the same original inode and bytes. Every later assertion previously hashed the configured descriptor, then hashed its kernel-descriptor alias again immediately before the version probe, then hashed the kernel descriptor after the probe.

The narrow change removes only the redundant first alias read for this paired current-process route. Complete current bytes are still hashed before and after the descriptor-bound version probe. Both original descriptors, the canonical pathname, `/proc/self/exe`, metadata/permissions, the current soft core limit, exact version/stderr and original descriptor closure checks remain. The configured-executable route without a kernel alias still hashes its own complete bytes on every assertion. No digest cache, admission result reuse, TTL, caller option or authority change was added.

A synthetic descriptor regression requires exactly two full kernel-descriptor passes and zero redundant alias passes per current-process assertion. Independent unchanged-metadata byte changes before/during the version probe, either descriptor inode, the named path, kernel link and core-limit drift all refuse. The generic configured descriptor retains its complete fresh hash and in-place byte refusal. Existing real filesystem/version/replacement and scan-lease regressions pass:29 tests total; strict types and zero-warning type-aware lint pass. No runtime profiling, controller/app call, native lifecycle or installed payload was used or changed. This reduces executable byte reads in each paired assertion from three to two; end-to-end admission timing remains to be measured by the lifecycle owner.
