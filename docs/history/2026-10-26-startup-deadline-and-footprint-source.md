## Source findings and implementation in progress

The current209 startup coordinator reuses a generic opener with a fixed
45-second native timer and 70-second host wait. Its worker is deliberately
paused by a separate source/constructor controller whose finite allowances can
exceed those limits. The native timeout label retains the last root-binding
guard before awaiting the project-open service; it does not identify root
identity drift. This establishes a source-level deadline mismatch, while the
retained case does not isolate every contributor to its elapsed time.
A separate startup program and wait derived from the complete bounded graph
are being implemented. Generic opening and individual request limits stay
unchanged. Final accounting and regression results will be appended.

Footprint source integration is proceeding in the same batch. The native GET_STR
path can read persistent caches, populate in-memory history/cache state and
schedule delayed cleanup across peer caches in the selected project. A source
reader must bind those original methods and producers and retain its own
dispatch intent, result and closure. Permission for the disclosed disposable
profile effects exists; complete implementation and effect verification remain
required. A raw inline-only shortcut would refuse ordinary stored drawing atoms
and is not being presented as general source support.

No new source reader or deadline correction has been live-validated. The next
release should combine these related implementations after focused checks and
required exact-commit CI, avoiding another installation for each prerequisite.
