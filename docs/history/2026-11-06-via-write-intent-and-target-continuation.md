# Via intent publication and original target continuation

The Via journal now publishes exclusive operation and phase artifacts through
the maintained managed publisher. Its fixed sequence requires native before,
whole-scene before, create, native after, whole-scene after and effect acceptance
before Save. Completion requires both original generations to exit and release,
complete closed SQL, a fresh reopened observation and reopened closed SQL.
Resource cleanup after a failed operation leaves the journal unresolved. It
does not turn an unknown Save into success.

`appendIntent("create"|"save", evidence, owner)` retains one opaque marker before
the first publication await. Publication settlement can return only that same
unconsumed marker. `consumeCurrentPcbViaWriteDispatch(token,stage,owner,plan)`
checks its exact original publisher, owner, plan and current intent sequence,
then consumes it synchronously. The native owner must await the returned
`assertPublished()` before calling the SDK. Artifact drift cannot refund a
consumed slot or permit a CAD call. The native Save effect token remains a
separate requirement; the journal token supplies durable intent only.

The public action schema is strict. Prepare accepts an original managed-fixture
operation identifier, a new Via operation identifier and the bounded Via data.
Execute, inspect, abort, observe-termination, release and settle-publication
accept only the Via operation identifier. No action accepts a path, script,
target object, SQL, remote handle or caller callback. This defines the eventual
wrapper contract; it does not register a tool or instantiate a native owner.

The SDK program now retains Array(9). Its ninth element is the original
synchronous target-check closure, captured once with the SDK objects and
private state. It derives the unchanged descriptor, project, tab and iframe
guards from the maintained opening observer. Later stages use that same
closure. They cannot adopt another equal-looking iframe between calls.

Full asynchronous registry observation runs during capture and preflight.
Create and Save use synchronous identity checks immediately before dispatch and
after their actual SDK Promise. Their acknowledgements and returned primitive
ID are retained before the post-check. No post-SDK registry RPC can wait behind
the selected main SQL fence. The later owner stage must perform its full
registry reproof after its original main effects settle.

Seventeen focused tests passed. The real managed publisher tests retain a lost
publication acknowledgement, settle its exact bytes once, reject copied/foreign
dispatch markers and detect artifact drift. Their original generated-plan
issuer is an explicit synthetic seam and supplies no native authority. The
original opening fixture proves synchronous reproof invokes zero registry,
document-open or child-identity RPCs and refuses original frame drift. Five SDK
program cases retain original Promises and once-only Save behavior. Full
TypeScript, strict type-aware lint and repository/skill/MCP-contract validators
passed with Node 24.18.0/npm 11.16.0 and core limit zero.

The actual native birth, opaque native effect issuer, original serializer/SQL
packet qualification and cache-excluded saved-generation coordinator remain in
progress. Those requirements stay enforced. No live CAD/native call, application
launch, shared helper regeneration or publication occurred.
