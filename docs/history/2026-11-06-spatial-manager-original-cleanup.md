# Original spatial manager recovery

The foreground manager now captures strict `spatial` and `component-spatial`
requests on its original `easyeda_control_pcb209_opening` client. Family,
operation and any original expected binding are comparison data. Only the
manager's retained original connection, transport, generation and request join
can select recovery. The adapter supplies no native owner or process authority.

Pending spatial calls admit a single bounded side-control lane for original
inspection only. After an SDK rejection/timeout, `cleanup-original` supports
inspection, original window observation, explicitly confirmed normal close,
termination observation, helper release and retained record settlement. A fresh
private-attempt inspection must retain the original intent/binding and report
not busy. The manager captures the HWND from its own original window result;
callers cannot supply operation, wrapper, binding, HWND, PID, native target path or code.
Close/release/prelaunch cleanup attempts are consumed before the original SDK
call. Unknown replies never grant a repeat. The facade remains responsible for
actual original window/root/Job and helper-release checks.

Prelaunch cleanup uses only the exact original intent and offered private
inspection flags. `cleanup-before-launch` maps to the typed
`cleanup-unlaunched` action. A purely local failed Component preparation can
still reach the facade's normal retirement proof without pretending a native
helper was created. No old purpose gains force-abort, Save, discard, owner
adoption or persistence authority. Component original-Job abort is a separate
possible follow-up, not part of this change.

A real manager with two synthetic MCP peers exercises both spatial families:
one original read times out, in-flight inspection remains correlated, foreign
selectors/refused HWND overrides produce no call, fresh private inspection and
window receipts inject the exact original close, and repeated close/release
refuse. The same retained child reaches authoritative synthetic facade
retirement and observed transport closure. These tests launch no EasyEDA app or
native helper. Existing original forward and Via recovery regressions remain
separate and pass.

The new strict data adapter is added to the foreground build's fixed script
input roster; the native/facade entrypoint exclusions remain intact. A sealed
in-memory frontend build passes original source/dependency/license/currentness
checks (1,730,989 bytes in this source state). It is not published. No generated
bundle, native helper, pin or released runtime file changes in this commit.
A running older frontend cannot learn these selectors; it must finish its
original cleanup and shut down normally before a separately verified updated
frontend is started. No Codex restart or native owner transfer is required.
