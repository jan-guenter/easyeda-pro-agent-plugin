## Findings and changes

The facade can start its supervised upstream and expose status while the EasyEDA companion never connects. A successful loopback TCP probe does not prove extension import or authentication.

The native import follow-up found a separate manifest defect. The source UUID `7e06d286b1ac846ef7eab9c7f2a9ee4` contained only 31 characters. Static inspection of installed public API `0.2.53.aee2f57a` showed that its manifest constructor requires exactly 32 lowercase alphanumeric characters. It clears a nonconforming UUID, and the import handler displays `The UUID of the extension is not up to specification!` before extension-storage insertion. The outer import handler can still return `true` after that inner rejection, so its return value is not import proof. The corrected UUID is `7e06d286b1ac846ef7eab9c7f2a9ee40`; the manifest test now checks the native format and rejects the former value.

The pinned EasyEDA Pro 3.2.149 public API `0.2.53.aee2f57a` declares `SYS_WebSocket.register(id, serviceUri, receive, connected, protocols?)`. Its implementation constructs the renderer WebSocket with the fifth argument as its protocol. The companion incorrectly supplied close/error callbacks as arguments five and six. It now passes only the four supported arguments and uses the synchronous native send/close methods. Unsupported create/browser fallbacks are removed; open/authentication timeouts, send errors and heartbeat expiry handle connection loss. [Official SYS_WebSocket reference](https://prodocs.easyeda.com/en/api/reference/pro-api.sys_websocket.html).

The final close-error check found no additional argument mismatch. Native `close(id, code?, reason?, extensionUuid?)` matches the adapter's one-argument call. Its permission check can throw before socket lookup; an unregistered ID otherwise returns normally. The native wrapper has no explicit already-closed rejection. The adapter deliberately retains any close exception as a teardown failure, so later permission enablement does not clear it. The Status toast does not establish the original exception cause, and a gateway Origin rejection alone does not explain a close exception.

The pinned app uses renderer origin `https://client`. Its native WebSocket therefore conflicts with the former blanket Origin rejection. The gateway now admits absent Origin or exactly one canonical `https://client`; duplicate, null, foreign, port/path-bearing and noncanonical values still fail. This is a deliberate transport-policy change, not authentication by Origin. Mutual HMAC, fresh nonces, exact authenticated index-build identity, key epoch, supervised backend process/socket ownership, session leases and disabled writers remain unchanged.

WebCrypto results from a superseded connection must not send proof/handshake frames over, or tear down, its successor. The companion rechecks its run, generation, exact handle and state after the awaited authentication operation and before error handling. Native socket IDs use per-attempt nonces, and native timer namespaces use per-runtime nonces, so retired cleanup cannot address a successor's socket or timers after a reload.

Status now exposes `bridgeConnection` with fixed event codes, saturating counters and timestamps. It stores no peer headers, nonce, key, frame or raw error text. Diagnostics do not enter lifecycle fingerprints, so unauthenticated failures cannot invalidate design authority. Zero observed upgrades is not a claim about TCP traffic; the historical last failure can coexist with a subsequently established session.

A stored stock MCP Pro Bridge 0.99.1 manifest is not the private authenticated companion, and stored metadata does not prove current enablement. This follow-up used native Extension Manager to import the receipt-selected private archive and freshly observed the companion's enablement and external-interaction permission. Its controls appear under Authenticated Control Bridge. Never rewrite IndexedDB or inject a substitute socket to work around import or permission gates.
