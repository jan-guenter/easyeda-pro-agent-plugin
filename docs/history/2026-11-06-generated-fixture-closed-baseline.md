# Generated fixture closed baseline

The managed importer now has a one-shot `capture-closed-import` action. It runs
only after its original tracked cleanup completed, while its original destination
directory and library watches remain held. It reobserves the original root/Job,
requires exactly the generated project file and no sidecars, holds the original
read-only file descriptor, copies to a new managed attachment, and reads every
SQLite table and row from that attachment. It never attaches SQLite to the native
source or writes a project database.

The source-specific qualifier admits only the generator's Via-only and Line+Via
archives. It checks the entire fixed native schema, all nonempty rows, every empty
table, both fresh branches, sole history head/chunk, all sequence rows, fixed vendor
defaults, initial structure and the exact decrypted plaintext. Native `L3` prepends
one `EDIT_HEAD`; the original generated stream follows byte for byte. The native
initial `DOCHEAD` has no ticket. This is a distinct format admission; generic
history/checkpoint guards remain unchanged.

The pinned main source is `app.js`, SHA-256
`52f51ce43cfebc81a362addde6cd27e39fa58c8fc1ab4ee5adacca4551e5ef0c`.
Its initial SQL is `TT` followed by migration literals `c2/u2/l2/f2/L2/dT`.
`scripts/check-managed-fixture-sql-template.ts` extracts those literals without
executing the application and reproduces their batches in a synthetic in-memory
SQLite database. The resulting 34 base tables have exactly two nonempty tables:
the fixed `sqlite=25.10.31.1` version and public LCSC vendor user. A fresh import
adds one selected-branch history table. Dynamic native UUIDs are linked across
all rows; extra users, caches, histories, sequences or editor records refuse.

Bookkeeping dates retain their raw source values. UTC SQLite defaults must match
their source-defined relationships and the native file birth/mtime interval. The
project's `So` local datetime uses one directly derived minute offset within
UTC−14..UTC+14. There is no current-clock lookup, time-zone enumeration, writer
age authority or modification to historical clock guards.

Successful qualification issues an immutable, in-memory read/open target. JSON
reports cannot recreate that token. The import owner transfers only that target
and the original archive bytes after explicit owner release. A fresh opening
generation must still prepare and verify a managed checkpoint, assert its own
original process/session ownership, and register the exact generated path. The
narrow generated checkpoint uses the existing checkpoint access, logical dump,
receipt and unchanged-source policy, then repeats the complete initial SQL and
raw history qualification. Ordinary opening may subsequently change the file.

Native `SE` scans only configured project roots. A temporary child directory is
not made discoverable by recording a recent path: `vu.save` writes `db_paths`,
while initial `ctx.projects` comes from `SE`/`nt`. Each fresh generation therefore
needs its own exact `/pro-mgr/api/client/openProject` prefix before public project
opening. That prefix may upsert one recent-path row and must disclose it. It does
not edit shared project-root preferences or scan existing design content.

Focused regressions use synthetic SQLite and encrypted history. They qualify the
initial unticked shape and reject extra auxiliary rows, altered seeds, additional
history, changed DOCHEAD, wrong sequences and substituted paths. Source-template
reproduction and offline tests do not establish native import, persistent
registration, completed delayed jobs, reader or writer acceptance. All connected
acceptance fields remain false until their original lifecycle evidence exists.
