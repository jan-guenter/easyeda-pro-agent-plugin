# Managed disposable fixture original import owner

Source implementation only. No EasyEDA process, native helper, MCP writer,
user project, SQLite project or registry was opened or changed by this work.
The excluded production project remains outside the route. Connected native import is not claimed.

The dedicated `ManagedFixtureImportCoordinator` now performs a concrete fixed
local import instead of treating archive qualification as import automation.
It generates one fresh versioned Via-only or Line+Via archive, publishes its
original bytes through both maintained private preparation stages, allocates a
fresh private Windows temporary directory, and calls the public
`sys_FileManager.importProjectByProjectFile` exactly once. The fixed File has no
native `.path`; the public `saveTo.operation = "Offline Client Local Path"`
discriminator selects the local branch and the manager feeds File bytes to
JSZip. The importer defaults `autoOpen:false`. No caller code, source archive,
destination, project, ID, geometry, SQL or configuration override enters it.

The original SDK Promise remains within `dispatchWithOrphanTracking` until it
settles. Its immutable nonce-bound slot permits observation without replay.
Unexpected returns, wrong/cloud project identity, rejection, synchronous throw,
owner drift and lost replies retain partial/ambiguous states. SDK settlement
never accepts delayed jobs, persistence, registration, or a usable fixture.
An unrecognized non-Promise return is no longer reported as a retained Promise.
The same compiled native shell traversal provides a retained exact empty
StartPage guard immediately before dispatch. The source-known empty project
is an own plain object with absent/undefined projectId and absent/undefined or
empty branchUuid, with history mode false; it is not a null-only test.

Every route checks the original index owner and Windows launch generation
around each await, fixes SDK/UI/manager/main bytes, seals an exclusive managed
operation journal before dispatch, and retains the actual journal for the
ordinary tracked cleanup owner. Cleanup closes the original application once,
observes original root/Job exit and original closed HMAC dispatch/session
evidence, and never replays navigation/import, Save, or force termination.
Directory release separately requires original root/Job exit, drains the
original watcher operations, observes original helper transport closure, and
preserves every generated/partial file. No file deletion authority exists.

Import-side phase publication now keeps the original mutable journal unchanged
until its exact candidate is durable. `settle-import-records` may finish only
that retained local artifact/journal candidate after a lost acknowledgment; it
cannot dispatch import, close, release, Save, or clear an orphan. Exact bytes and
both allowed journal states are rechecked before publication. A known refusal
before the importer call, after the maintained engine cleared its unused
capture, becomes a terminal `import-not-dispatched` record so the settled
environment owner can close the original ordinary launch. An actual ambiguous
dispatcher remains quarantined and retains all native effects as unknown.
