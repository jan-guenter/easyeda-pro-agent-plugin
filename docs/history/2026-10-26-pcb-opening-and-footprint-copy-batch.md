## Combined source changes

- Both ratline launch purposes use an exact dedicated PCB-opening program. Its
  native encoder supplies the remaining time from the original launch stopwatch.
  The tool wire has no duration field, and opening cannot reset the one-hour
  launch allowance or consume the cleanup reserve. Generic/default PCB opening
  retains its existing timeout. Source and navigation qualification use the new
  exact program identity.
- Opening acknowledgment requires a decoded successful reply. Refused and
  timed-out replies remain consumed and report no acknowledgment.
- Assignment inspection retains the fixed step, reply count and last bounded
  immutable reply with digest and byte length before decoding or the following
  owner reproof. Existing lifecycle inspection exposes these diagnostics. No
  command, retry or acceptance exception was added.
- Separate footprint copy-v2 preparation models ordinary records, repeated
  history fragments, tombstones, exact raw body bytes and the pinned native
  `Object.keys` order. It binds the original completed inventory and source plan,
  excludes unsupported metadata/dependency effects, projects append records and
  checks the complete closed SQL effect. The original v1 modules remain intact.
- Tool descriptions now distinguish exact keyed/header equality from the order
  observed in two matching native source samples. They no longer describe the
  source reader as a single-fragment CANVAS/PAD/LINE reader.

Copy-v2 is pure preparation and comparison. Supplied source order and actor/clock
witnesses do not establish original live provenance. No copy writer is mounted.
Producer completion, generation closure, upload replay exclusion, saved/reopened
verification and execution remain false. The tests do not convert these claims
into connected validation.
