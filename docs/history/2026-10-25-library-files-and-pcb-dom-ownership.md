## DOM request ordering diagnosis

The timeout is consistent with a request-ordering deadlock. Chromium routes
`Debugger.getScriptSource`, breakpoint operations and resume through its
interrupt-capable channel. DOM and frame-tree queries use the main-thread path,
which an instrumentation pause does not service. The router awaited such a
query before allowing the paused script to continue.
[Chromium DevTools session source](https://raw.githubusercontent.com/chromium/chromium/146.0.7680.188/content/browser/devtools/devtools_session.cc).

This source inference explains why extending the timeout would not repair the
ordering. The correction under development establishes an ordinary, owned
breakpoint at the qualified source's first location before requesting DOM
ancestry. A separate inert V8 process has demonstrated the transition for the
six-byte window hook and a PCB-shaped outer function, with no movement past
the requested location. This is mechanism evidence, not an EasyEDA success.
