## Ordinary closed-runtime release

The new `release-closed` action separates observed application termination from
release of the original helper and runtime reservation. It requires the current
original ordinary owner, exact launch and termination receipt digests, and
explicit confirmation. A durable one-shot intent precedes release. The original
helper transport must close before matching runtime allocations can be cleared.
A failure or lost acknowledgment consumes the attempt and retains allocation;
historical JSON cannot reconstruct ownership or authorize another release.

The guard distinguishes a diagnostic coordinator that has never attempted
native allocation from one that has allocated, failed or released an owner.
The allocation-attempt observation is monotonic. An inactive reservation alone
is insufficient evidence. Project, writer and previously allocated diagnostic
owners remain outside ordinary release scope. This path does not close or kill
an application, release a host facade, or bypass a design recovery gate.

The source integration and its focused verification are being completed in
this batch. The installed release does not contain this action, and no connected
release through the new route is claimed.

## Enriched public catalog lookups

The new `search-footprints-by-name` and `get-devices-by-lcsc-ids` actions are
anonymous vendor HTTP task equivalents. They do not execute the corresponding
public SDK methods or access the application, bridge, desktop database or user
profile. Explicit network confirmation permits one name or one to five distinct
uppercase LCSC identifiers to be sent to the fixed vendor service.

The first lookup is followed by one exact metadata GET for every returned
candidate. At most five candidates and six total requests share one deadline
and aggregate body limit. Every candidate must satisfy the applicable owner,
type, identifier and reference checks. Duplicate candidates, missing witnesses,
contradictory metadata, overflow or any later failure refuse the entire result.
There are no retries, partial results, pagination, credentials, arbitrary owners
or arbitrary endpoints.

Linked symbol/footprint assets, geometry, images, 3D, datasheets, prices and stock
are not followed. Sequential replies are not an atomic snapshot. Empty results
do not prove absence, and references do not establish pin-to-pad mapping or
manufacturing suitability. Missing optional device public/path flags remain
explicitly unverified. Two initial anonymous development probes lacked the
complete witnesses that motivated enrichment; they are not live validation of
the composed routes. The iframe-existence omission now records the installed
constant-false stub rather than implying a usable observer.
