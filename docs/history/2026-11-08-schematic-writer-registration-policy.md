# Separate writer registration policy

The Main runner now recognizes a fourth original registration issuer for the
seven-record schematic Relevance writer. Its private intent, original factory,
closed checkpoint and selected project/page/schematic binding remain distinct
from the saved schematic reader, Via saved reader and footprint inverse.

Enrollment uses the existing fixed registration codebook and three exact native
breakpoints. A continuation requires the original pending writer dispatch across
each await. Completion requires the actual awaited sequence. An original prior-path
result can settle only the unused writer sequence; it creates no SQL callback or
await acknowledgment. Copied intents cannot enroll, claim completion or skip work.

The Core's original lookup map is initially unissued. This runner policy does not
enable the still-separate writer registration/opening path or any Modify/Save
stage. No saved-reader intent is reused.

Validation passed the 22 focused Main, schematic subscriber/duplex transport and
inverse-reference integration cases, both TypeScript checks and strict type-aware
lint. The transport integration preserves the latest inverse GET/result/reference
lanes alongside the new schematic subscriber marker. No helper, process, app,
registration, Modify or Save was dispatched by this source change.
