## Fresh-context subagent experiment

The fresh subagent started a distinct MCP process with separate stdio, using
the latest installed package. It did not share the root controller's serving
process. Its connection entered the expected ownership-conflict mode because
the root facade still held the original exclusive lease. One passive startup
snapshot reported that owner and confirmed no lease was acquired. The conflict
connection did not retry or take over control.

A fresh subagent can therefore load a fresh package, but fresh context alone
cannot transfer control. A supported handoff must first finish original native
cleanup, drain or refuse active work, close the old upstream/gateway, release
the original lease, and permanently prevent that old connection from doing
live work. The replacement must be started after release and independently
admitted. No host gateway was killed, no cache patched and no lease edited.
