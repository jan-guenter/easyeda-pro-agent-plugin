## Scoped normal closure

`project-open` adds strict `request-normal-close` with the original operation
ID, `confirmNormalClose:true` and `acceptUnknownFileEffects:true`. Only the
original untransferred owner of an orphaned, stopped disposable opening can
use it. It accepts no HWND, PID, replacement fingerprint or code. The native
helper observes the original owned window and requests normal close after a
durable one-shot intent. It never enters a bridge scope, selects Save/Discard
or forces exit. Publication uncertainty and a missing acknowledgement do not
permit another close. The helper's shared per-Job reservation also prevents
repeating the native close through another route.

The action leaves quarantine intact. Existing `retire-after-termination` still
requires original process/Job exit, closed authenticated session and released
dispatch proof. Acknowledgement is not termination or saved-content evidence.
Lost owners remain unsupported; historical JSON cannot reconstruct them.
The new action cannot be loaded into a running older owner to rescue it.
