# Original watcher and React dispatch data

The passive notification collector derives the ordered file/main/undo/redo jobs
from the original command-entry snapshots and complete ordered watcher Maps.
It independently requires the original stores to have been idle; an older pending
notification cannot be adopted as this command's job. The supported census is
four jobs and at most eight watchers in each value-store Map, with the main Map
empty. Original numeric watcher keys and complete Map order are retained.

Only the source literal's own `setState`/`callback` record is supported, in that
order, with regular data descriptors and callback exactly undefined. Dispatchers
must be distinct actual native bound `i0n` functions with null bound receiver and
two native bound arguments. The collector qualifies the source target and `Bxe`
reducer, retains the original fiber/queue pointers and complete descriptor
snapshots, and checks the literal queue fields, same bound dispatcher and numeric
pre-dispatch state. Newly exposed values receive non-Proxy packets before their
descriptors or prototypes are traversed.

Native `[[BoundArgs]]` arrays are Inspector copies. Fresh metadata and JavaScript
identity comparisons rejoin their elements; objectId text cannot prove that
relationship. Immutable prototype/function snapshots remain checked around
dispatch metadata and held returns. The full mutable React snapshot is historical
data after an actual delegate runs. React internal invariance remains false;
this leaf does not invent its delta or recursively qualify all React work.

The original controller separately owns every event, arm, resume, returnValue and
Promise settlement. This leaf supplies readonly job/visit/dispatch/return data and
the fixed checkpoint-only store comparison. It includes a fixed identity retain
and same-prototype check for an actual visitor Promise. The strict Promise decoder
accepts pending or fulfilled undefined metadata and issues no ownership or
settlement authority. Queued completion, worker observation, Modify completion
and Save authority remain false throughout. Generic snapshot/SAME rules and all
existing purpose guards are unchanged.

Read allowances are derived from the finite collector paths. Preparation is
24+4J+33M normal requests and 19+11M helper sources; J is at most four and M at most
24. The complete passive collector allowance is 3,015 normal requests plus 2,194
helper reads. Controller-selected Promise operations are separately listed and
are not counted again in that total. Controls and resumes belong to a separate
grammar. The configured three-watcher preparation exercises 139 normal requests
and 52 helper declarations.
