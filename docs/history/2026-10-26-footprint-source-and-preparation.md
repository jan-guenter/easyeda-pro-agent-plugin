## Native copy producer findings

The new [creation source qualifier](../../plugins/easyeda-pro-control/server/src/current-footprint-copy-create-source.ts)
checks the complete pinned project worker and UI source strings plus21 selected
UTF-16 spans. The installed files matched worker SHA-256 `0e7a474385029ac4f69dac08abdfd8beec7346aea8c2a4f71d5afb78bb454046`
and UI SHA-256 `3515d4c299b353fa7bcd0d859f0b8b59b7eae39b5dc243b2c27f2e54a60a1ee6`.
The qualifier issues a private source token; a copied report cannot recreate it.
It opens no file and evaluates no supplied code. It grants no native receiver,
source route, actor, clock, parser, upload or writer authority.

`Tg.create` calls `buildString` before requesting the existing footprint source.
`buildString` allocates the destination and registers its document type before
its first server-time await. It advances the metadata ticket before the later
source request. A failed clock or source response therefore cannot prove that
nothing changed. The method subsequently awaits `uploadLocal`, ignores the
returned success field, and returns `success:true` with the result of `get`.
That result can be null. Neither acknowledgment establishes completed upload,
saved contents or permission to retry.

The worker's source request crosses its notify bus into the UI. The UI's
extension-library lookup precedes its `isProject` branch. A project argument
alone does not exclude extension-library routing. The project branch checks
project presence, calls `FOOTPRINT.GET_STR`, and converts a missing or falsy
message into a successful empty string. A future copy owner must bind the
original responder and registry exclusion, then validate the complete source.

`GET_STR` calls the existing consistency compressor. Lazy history-cache loading
can populate `historyMap`; a missing native cache chunk can invoke the history
parser through `getFlowParse` and `mg`. Successful compression schedules cache
cleanup. The cleanup reschedules itself while a cache promise remains pending.
A prior cache-only source observation does not prove that these later producer
paths were avoided or completed.

`uploadLocal` parses the new history before attempting its asynchronous
Cache.put. A failed put can retain data in `bufferUploadData` and call
`uploadCloud`; a successful put schedules the buffered upload producer and
publishes pending state. The source qualifier records these distinct branches
without treating either as durable completion. The manager's own-undefined
user observation and two server-time responses still need original runtime
provenance; supplied source bytes provide neither.
