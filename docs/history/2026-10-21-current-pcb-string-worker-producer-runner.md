# Original-worker producer collector

`current-pcb-string-worker-producer-runner.ts` combines the reviewed serial,
debounce, cooperation and upload readers with six callback qualifications and
eight gate/publisher method qualifications. It leaves the earlier dormant
two-session 34-command producer runner unchanged.

This is a private observation component, not a writer. Its transport adapter
must own the already admitted complete worker source, original worker session,
unique execution context and native process/target association. The collector
does not discover or attach targets and cannot adopt caller-supplied handles or
previous JSON reports.

## Fixed grammar and ownership

The command module exports five fixed evaluation selectors and fifteen fixed
function programs, plus each call's exact argument count and return mode.
The native integration reconstructs these programs from `workerProducerPhase`,
not supplied program text. A tagged private envelope distinguishes worker
properties from the existing page properties; the tag never reaches Chromium.
The PowerShell/C# boundary accepts fixed phases and bounded identifier fields,
checks the exact 58-step order, binds its first original worker session/context,
and permits only an early release to skip the remaining reads. Every program requires side-effect
checking, silent evaluation, no Promise awaiting and no user gesture.

| Sequence | Requests |
| --- | ---: |
| PROJECT, eight gate/publisher methods, fresh gate scope and sample | 14 |
| uploadStructure wrapper, state and callback qualification | 6 |
| structure wrapper, fresh serial/debounce state and callback | 12 |
| Cooperation wrapper, state and callback | 6 |
| Upload wrapper, state and three callbacks | 12 |
| Fresh upload/buffer/drain environments and joined sample | 7 |
| Original worker object-group release | 1 |
| Total | 58 |

Only the original worker session receives commands. All selected objects use
`easyeda-pro-control-string-worker-producers-v1`, including objects returned by
function calls. The one-shot attempt is consumed before the first asynchronous
request. Original ownership is checked before and after every read and again
after cleanup. Owner loss permanently invalidates this collector; reconnecting
or restoring an external boolean cannot revive it.

Mutable-state reads use freshly qualified V8 scope wrappers. Callback-only
selection can reuse the source-defined immutable function bindings from the
preceding sample; no later mutable-state sample reuses those wrappers. The
buffered-environment reader reacquires the upload, buffer and drain scopes and
compares their captured PROJECT/function references and scalar snapshots.
Sequential matching is not an atomic snapshot or an observation interval.

## Evidence and failure

The seven original JSON-text replies are retained without decode/reserialize
substitution. Each text is limited to 16,384 UTF-8 bytes, their total to 114,688,
and the decoded observation to 131,072. The native response contract allows at
most 65,536 bytes per reply; the metadata decoders also bound their input shapes.
Public integrations should expose a bounded summary and journal the raw text,
not mistake remote object handles for durable ownership.

A successful observation is frozen and registered by object identity in a
private issuance map, only after the original release and final owner check.
`requireOriginal` additionally requires that exact collector instance and a
still-current original owner. The exported retained-reply accessor establishes
historical runner issuance only. Copies and JSON reloads cannot be adopted.

On any read, decoding or owner failure, the remaining reads stop. Cleanup still
attempts one release against the original worker/group, without a new target or
session. The original primary error remains the aggregate's cause and first
error; cleanup and final-owner errors remain separate. A branded bounded
failure record exposes the fixed phase, read-request ordinal, cleanup status
and retained sample names. Raw arbitrary exception text is not a public failure
record. Previously received sample text remains available from the original
failure object; malformed reader text is retained when its bounded envelope
was valid, without being accepted as a sample.

## What this does not establish

Four callback arrows still hide their lexical receiver. Matching their exact
source and location or membership in PROJECT's wrappers does not prove that
receiver. Their scopes are not treated as inspectable receiver proof and none
of the six callback bodies is invoked.

The publisher tuple does not establish native BroadcastChannel ownership, its
hidden onmessage receiver, external peers, compiler publishers or backend
destinations. Raw empty-looking timers, promises and batch counts do not prove
queue completion: upload drain can clear markers before its awaited work
finishes. Nonempty sampled batches are reported as such, not rewritten as idle.
Absent, undefined and boolean `isSyncing` remain distinct.

Accordingly the observation explicitly keeps hidden receiver verification,
complete publisher coverage, write-destination containment, atomic snapshots,
continuous observation, queue completion, Save authority and execution
authority false. The original String owner now invokes the collector after its
versioned precreate sweeps, within the existing consumed observation stage. It
rechecks retained UI/PCB/worker contexts, parent target/frame and installation,
then records the combined observation in the append-only journal. Historical
journal loading cannot recreate a live collector or adopt its issuance. No new
SDK method or connected writer coverage follows from these source tests.

## Focused verification

A synthetic Inspector fixture compiles the exact inert excerpts at their
qualified function locations in one worker-like context. The complete collector
uses all 58 requests under side-effect checking, with no debugger pause,
callback/publisher invocation or instrumented trap. Focused cases cover foreign
script/project identity, malformed samples, channel plus cleanup failure,
initial/final owner loss, report-copy rejection, immutable exact raw text and a
nonempty cooperation batch. These are synthetic results, not live EasyEDA
validation. Production projects are outside this component's test scope.
