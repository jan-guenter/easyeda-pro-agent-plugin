# Inverse build retains shared saved-reader codecs only

The explicit `inverse-closed` build branch now emits only the immutable shared
CacheStorage, native metadata, load-worker and two early-actor message codecs
required by the original inverse purpose. It emits no Via saved-reader factory,
instance state, sender, action admission, PowerShell dispatch or owner smoke.
The inverse's own constructor, Main/discovery hooks and request ceilings now
anchor directly to the existing base/schematic scaffold. No dormant Saved Via
runtime or throwing compatibility factory is needed.

The shared scalar validators, complete program/table bytes, options, hashes and
ID/field bounds remain exact. The two actor codecs are retained from their exact
maintained source lines: the inverse actually calls the early-stage encoder,
which also requires its original actor encoder. Default diagnostic and schematic
helper outputs remain byte-exact against the pre-change private generation.
Neither runtime purpose can select this build projection or supply code.

At this source boundary, complete inverse compiler input fell from 2,090,844 to
2,052,270 bytes, recovering 38,574 bytes under the unchanged 2 MiB cap. Stored
helper size fell from 1,489,775 to 1,454,563 bytes. Complete broad generation and
the closed inverse driver repeat byte-exactly. Later SQLite installation and GET
result changes still require a fresh combined measurement; this record does not
claim that unmeasured union.

Two focused tests pass. They compare all retained codec bytes against the
unchanged default family, prove Saved Via runtime/dispatch absence, retain the
full existing inverse smoke roster, exercise whole generation twice and refuse
edited codec blocks or unknown build modes. Initial isolated-fragment fixtures
omitted prerequisite switches and then failed to expand packed review source;
correcting those fixture preconditions required no production guard change.
Both TypeScript configurations, changed-file strict lint and whitespace checks
pass. Linux .NET C# language version 5 compiled the complete new inverse source
and passed all 28 existing inverse pure smokes. No smoke, request budget, source
cap or released role was removed or widened. No tracked helper, pin or bundle was
regenerated, and no application or Windows helper was started.
