The private drain cursor follows the actual history response, dropped local-save
IIFE, deferred first sync, source finalizers and three independently awaited
cache jobs. It imports no runtime owner and issues no ownership or persistence
token. Its host must come from the original Core registry, using the already
qualified upload-request and local-upload captures on the same worker.

The response first joins the actual completed Main history UUID/body digest. A
retained cloud Promise is the sole second original `task1` member, independently
joined later by JavaScript reference equality to `batchReturned.t`. Its actual
fulfilled PromiseResult must equal the original `cloudReturned.c`, not an equal
JSON object or independently wrapped Inspector ID.

The DAG permits local-save, delta-flow and final-head cache jobs to overlap.
Every job retains its own original entry, async closure, retry0 frame, returned
Promise and success frame. The delta/head bytes late-bind only after the genuine
changed-head replay continuation. Initial and post-history cache authorities do
not transfer. The original dropped local-save key retains its own bounded
source-produced timestamp; it is never predicted from the Save clock.

Two exact old-upload deletion events delegate to the separate original-owner
four-message lane. The drain does not add cache-delete grammar, retry a delete,
accept a caller URL, or read a second event stream.

The first `syncCloud()` call occurs while upload is active and must reach only
its source-owned deferred return with `pendingSyncCloud` set. It cannot issue a
GET. The later full changed-head call belongs to its separate seven-role cursor.
Uploader callbacks and cleanup can interleave with that later sync and the cache
jobs. Their causal prerequisites are checked independently.

braces expose the original invocation's async Promise. Each is retained into
our own object group before resume. Inert JavaScript reference comparisons

The cursor checks nine original Promises: three puts, the original scheduled
buffer task, buffer and batch outer calls, uploadCloud, deferred sync and dropped
local-save IIFE. All must actually fulfill with their expected result. Matching
source finalizers, empty original work collections and the genuine completed
changed-head cursor are additional requirements. Quiet collections alone cannot
complete the drain. There are at most two actual metadata passes; an unknown ACK
or rejected/malformed result consumes the attempt and fails closed.
