# Prehistory structure observation

The shared original structure observer has a separate prehistory route. Its
`releasePrehistoryPacket` consumes the original body reservation once and
independently checks the selected project, branch, document, head ticket and
complete source-derived metadata tree before resuming the held packet. It
does not borrow the history-completion token or issue one from matching data.

`observePrehistoryCompletion` requires the original publication already
consumed for that exact shared origin. It checks the actual packet's project,
branch, ticket and complete structure hash, then follows the same original
response, callback, task removal, promises and two serial finalizers. This
uses the existing fixed commands and request reservation. A distinct retained
result records body/publication joins while history, upload-frontier, closed
SQL and persistence claims remain false. The original history route and result
schema retain their existing meaning.

A prehistory-only result keeps its breakpoint custody until original root and
Job exit. Cleanup never treats that result as completed history or resumes a
held publication. Production body/publication issuers and the continuous
pre-action producer prefix remain separate prerequisites; no writer or Save
eligibility is added here.

the old history route, separate reservation/publication ordering, wrong body
or hash refusal, no premature response resume and exit-only retirement. The
tests use explicit synthetic native-registry and full-source seams; real
observation, validation and continuation state machines run unchanged. No
