# Passive UI Echo event and receiver preparation

The new five-module Echo-event leaf qualifies actual Event data and prepares
one selected page callback. It is unmounted. The original Core still owns every
event/control boundary, publisher/loopback completion, callback body and
timer/Canvas/SDK settlement. No receiver, trust, delivery, worker, Modify or Save
authority is issued; every such receipt flag remains false.

The base is `a173be4796993c542e4e9deda6e12c53dc33b044`, including the sealed
`6bb10594` Echo handles. The seven new source/test files have SHA256 index digest
`a3454cc2988f3a6bc13e0fdb64a9d31dc77cb67d968a9573919a35be52150709`.
Raw command logs, complete own-session replies, pidfd exit proof and the fixed
program inventory remain outside the public repository.

## Event data

The [collector](../../plugins/easyeda-pro-control/server/src/current-schematic-relevance-modify-echo-event-collector.ts)
captures only `[this,K]` at the original handler boundary. JavaScript reference
checks bind this to publication roots8 slot 1 and K to the actual Event. The
instance must pass complete non-Proxy MessageEvent metadata before its own
isTrusted getter is captured and qualified. The prepared same-realm Event and
MessageEvent prototypes and seven getter references must still match.

Only then do native Event reads require trusted true, message type, phase 2,
target/currentTarget equal to the original BroadcastChannel, source null and
origin equal to the separately reread original serialized native origin. Data
stays opaque until its correlated metadata is qualified. Envelope, message
array and row each receive separate metadata and descriptor stages.

The exact canvas row has nine values: id, ticket, body, TEXT, client, true,
unique, false and order number. The message contains exactly that one row.
Expected page/id/ticket/body/client/unique values come from the original UI
pending frame9 and pristine7, never worker object IDs. The flat thirteen-scalar
result retains sender UUID and an explicit order-number presence bit plus
number-or-null value. This preserves undefined through CDP JSON encoding.
Core must separately compare it with its original worker evidence. Scalar
equality does not establish matching transport or sender ownership.

## Selected page callback

The receiver preparation joins the retained selected page, manager, publisher,
CM, compiler channel and data bus. The publisher must have the exact XE/main or
MP/child class ancestry. The topic template and actual page topic must match;
the roster contains exactly one running unsafe task with its retained callback.
The class, initProject, callback, channel and task methods require complete
source/script/location metadata. The callback comes from the pinned
initProject site, not a similarly shaped bus copy.

Its empty function name, opaque scope/prototype handles and current onUpdate,
locker and temporary-unlock branch data are retained. Scope metadata proves no
lexical this. No callback, canPush, running, execute or initializer is called by
the preparation. String coercion and unsupported accessor shapes refuse.
Complete descriptors, unknown strings/Symbols, order, prototypes and signed zero
remain covered by the unchanged snapshot reader. There is no recursive UI audit.

Each API has six graph stages, twelve prototype waves and at most 384 newly
qualified objects. Its preparation bound is 1,356 reads, plus two separately
bounded publication reproofs of 24 reads and 24 helpers each. Each API therefore
reserves 1,404 reads and 1,404 helpers; both total 2,808 reads plus 2,808 helpers.
Controls remain zero.

The fixed book has 23 role bodies totaling 64,275 bytes. The eighteen program
members total 49,152 bytes. Exact existing helpers are reused for the five raw19
graph roles, Event sameRead, three original Echo native roles and the original
publication reproof. The origin reader differs only in its fixed result-array
wrapper. These are source-body byte counts, not a measured encoded native table
or compiler result; Root owns lossless pool sharing and actual codec admission.
