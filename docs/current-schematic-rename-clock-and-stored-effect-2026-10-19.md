# SCH rename clock and stored-effect groundwork

Date: 2026-10-19. This is private implementation and synthetic evidence. No
new tool, route, native call, design edit or Save is enabled by these modules.
No production design was accessed.

## Implemented scope

Three SCH-specific modules extend the existing original-owner startup chain:

- `current-schematic-rename-writer-clock-program.ts` compiles a fixed N0
  renderer/server clock observation. It retains the no-editor project holders,
  neutral startup holders, SCH child AST, dormant auxiliary panels and both UI
  actor objects around its single server-time RPC. It accepts only exact target,
  expected actor and startup fields. The response binds the complete request
  hash, including startup expectations. It does not query or mutate project
  records, Save, flush queues or observe the worker's private actor/client.
- `current-schematic-rename-clock.ts` requires the original SCH startup and the
  SCH-issued writer-transfer owner from the same generation. It retains their
  identities before awaiting and reproves both after every Windows-token or SQL
  preparation await. Separate original launch, capture, pre-sample and armed
  Windows observations bind UTC ticks, QPC order, helper/Job identity, captured
  root and timezone rules. Distinct pre-sample and armed observations must
  bracket the supplied renderer sample within 10 seconds. They establish fixed
  60-second document/backend comparison windows, not an extendable deadline.
- `current-schematic-rename-stored-effect.ts` accepts the original SQL
  preparation, metadata projection and completed before/after readers. It
  requires the complete original history followed by exactly one new chunk
  containing `EDIT_HEAD`, SCH `DOCHEAD` and `META`. Only document/backend
  timestamps are learned from that chunk. The document time must equal the
  separately supplied native-reply time. Frozen title, actor, client, target,
  history and clock windows come from the pre-write preparation. Existing SCH
  bind/verify functions compare the complete SQL effect, including unrelated
  tables and peer assets. An original-object-only accessor exposes the verified
  decoded history for later lifecycle composition.

No PCB WeakMap token is converted into SCH authority. The reused panel guard,
startup guard, clock transport and historical decoder are document-neutral
checks. Their historical filenames do not confer PCB or symbol ownership.

The clock plan currently supports only a locked history head. It never accepts
an `agedHead` parameter. An unlocked head must wait for a separate original
native age observation and reviewed binding path. The SQL model's supplied-age
branch remains independent and does not become runtime-qualified here.

## Claims deliberately not made

The clock plan takes the document sample as data. Running the fixed collector
in a test VM does not establish that a future coordinator retained its actual
native reply. `documentSampleProvenanceVerified` remains false. The original
Windows tokens and SCH lifecycle identities are real requirements, but they do
not turn supplied renderer data into original dispatch evidence.

The observed UI actor must match the full actor strings selected from the
original SQL users table. That equality does not observe the worker's `Dg.user`
or `Dg.client`, prove backend actor provenance, or bind all native producers.
All corresponding verification flags remain false. The plan retains explicit
common-OS-clock/no-intervening-change assumptions and does not claim direct app
clock observation, continuous clock stability or a verified future write time.

A successful SQL comparison proves the supported complete data relation only.
It does not prove application closure, SCH subscriber completion, queue drainage,
upload replay exclusion, dispatch origin or saved reopening. Its original-reader
identity is not a Windows process/Job termination proof. Those flags stay false
even when every compared SQL cell is correct.

Preparations are one-attempt per original startup and issued writer owner.
A failed preparation cannot be retried with another sample or extended clock
window. Copied JSON plans, replaced owner tokens and equivalent fresh SQL reads
cannot recreate a successful original comparison.

## Focused verification

The focused tests use the fixed generated program in a synthetic SCH renderer,
source-qualified synthetic Windows helper streams, and real completed readers
over synthetic encrypted native-history SQLite fixtures. The clock-plan tests
replace only the SCH startup/transfer issuer in an isolated VM, not the real
Windows token or SQL preparation/comparison functions. This is not a connected
writer test.

Cases cover normal N0 sampling; target/startup/actor substitution; getters and
Proxy traps; changed receiver, clock, project, child AST and panel holders;
timeout with no later work; copied/repeated Windows observations; each awaited
clock stage and SQL preparation losing its original owner; expired plans;
unlocked heads; historical/UI actor mismatch; altered title, actor or timestamp;
wrong document type; additional history records; changed peer asset SQL; and
copied preparation, reader and completed-effect objects.

The initial N0 test run found a synthetic fixture's wrong timeout constant name.
That test fixture was corrected; no guard was removed. Final focused counts,
strict types/lint and source hashes are recorded in the release checkpoint.

## Remaining before a callable SCH rename

Retain the actual N0 reply and independent Windows brackets under the original
dispatch owner. Qualify the backend actor/client and complete producer state.
Bind the clock plan to one durable journaled mutation attempt, then retain its
actual acknowledgment and post-dispatch clock samples. After original root/Job
termination, bind the full stored SQL relation to that closure and prove fresh
generation saved metadata, unchanged child roster and final closed SQL.
Do not substitute a fixed wait for the delayed SCH subscriber's completion.
Public registration and disposable live validation follow those steps.
