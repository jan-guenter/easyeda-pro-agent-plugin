# Capability matrix

Use supported typed APIs first. Native controls cover genuine API stubs and dialogs. This matrix describes the current source package; an older installed snapshot may not contain these tools. Historical external-tuple admission and installed-generation evidence do not admit this new source. Exact reads and typed operations still require their pinned implementation identities and operation-specific proof.

The separate EasyEDA3.2.209 profile registers thirteen tools: API reference,
local discovery, status, calculations, system observations, language/viewport
readers, tab-count/active-identity/shortcut observations, public catalog queries,
ordinary launch and disposable project/PCB opening with layer and primitive observations.
It admits the source-reviewed fixed16Math and18Unit/Environment subsets through
their own exact runtime checks. Two utility argument sets passed on the prior
installed release; that does not validate every method or this source payload.
None of the older native/private design-content, project-opening or metadata-writing routes
below is registered there. Its separate [209 opening route](current-pcb209-opening.md)
uses its own restricted original-owner lifecycle and source pins; it can trigger
ordinary automatic persistence, but offers no explicit Save or writer. Its
one-shot `observe-layers` stage provides two matching native layer samples,
the public layer projection and enabled copper count; it does not establish
physical stackup, complete startup or a saved baseline.
The separate `observe-primitives` stage returns two matching Line/Arc/Via and
parentless String loaded-view projections with ordered IDs. Its256-row per-family
and384KiB aggregate bounds refuse excess output. It does not include raw models
without views, other families or complete connectivity, and is not SDK-instance
parity. Scoped connected cases on earlier installed generations do not admit
this source payload or untested family shapes.
The separate `observe-extended-primitives` stage adds Component, Pad, Attribute,
Dimension and Image projections with ordered IDs, Attribute parent groups and
explicit Component metadata presence states. Its limits are 256 rows per family,
256 Attribute groups and 384 KiB aggregate output. No child-pad or reciprocal
ownership, complete asset, rendered geometry, source or saved-state proof follows.
Earlier connected cases likewise do not transfer to this source payload.
The separate `observe-selection-relations` stage reads all nine families and
brackets each of two matching snapshots with native identity and selected-ID
reads. Optional `componentIds` requests up to 16 ordered child-pad groups. It
resolves every selected ID or refuses, and compares child IDs/scalars with
global Pad DTOs. This adds no reciprocal ownership, symbol-pin mapping or
child-handler geometry proof. The stage uses one CDP call, up to 58 local RPCs,
256 rows per family and 384 KiB aggregate output. Its connected validation is
pending.
Repeatable `query-observation` reads published primitive snapshots by exact
result-record digest. Family queries support IDs and documented exact filters;
selection and component-pad queries require the corresponding recorded stage.
These disk-only historical projections do not dispatch CAD calls, adopt an owner
or establish current state. See [recorded observation queries](current-pcb209-opening.md#query-a-recorded-observation).
The new ratline source verifier and finite-role
model are dormant implementation groundwork, not an executable capture route.
The [public catalog queries](current-system-library.md) require explicit network
confirmation and use fixed credential-free vendor endpoints, without local
application/database access. Footprint/symbol/device search, symbol/device
metadata and known footprint lookup are task equivalents, not SDK execution. Device references
are not verified pin mappings; search candidates are not exhaustive matches.

Current safety restriction (October 10): schematic compiled topology is disabled.
The installed netlist File getter can annotate components and invoke Save All.
All schematic transactions or recovery paths needing that reader stop at the
missing proof; do not bypass it with UI export or a generic SDK call. Schematic
netlist/BOM/document and PCB netlist/BOM/PDF exports are also refused because of
hidden Save All. Simulation export requires an unsupported NGSPICE editor.
Historical observations below do not override these current restrictions.
Separate sealed single-page display and wire-reroute observers avoid that
compiler, but their transactions are also blocked by the later structure-job
finding below. Their retained contracts are not execution exceptions.
PCB/footprint navigation also needs passive preference-side-effect admission.
See [native navigation limits](native-ui.md#navigation-preference-side-effects);
project-file invariance does not cover global preferences or backup pruning.

Query offline `coverage` for current generated method and route counts, and
`sdk-reads` for its narrower fixed-read catalog. Counts describe implementation,
not whole-method live validation. The tool list depends on the admitted runtime;
check the actual registered catalog rather than inferring it from this matrix.
Each live capability still needs its own exact admission.

Eight legacy generic symbol/page/container metadata-writing routes are also blocked pending
operation-owned structure-job completion and exact SQL-effect proof. Historical
document-record tests below do not prove that later-discovered requirement.
See [the exact restriction](libraries-and-eco.md#structure-write-completion-restriction).
Pure schemas and historical evidence remain readable; a nonterminal affected
journal cannot become complete through ordinary reconciliation.

The same job is scheduled when native Save republishes pending geometry without
its pending flag. Schematic-page, symbol and PCB design transactions are therefore
blocked too, including the sealed display and wire profiles. New apply, Save,
inverse, repair and nonterminal reconciliation refuse. Footprint transactions
retain their separate guards. The design descriptions and historical results
below describe retained source contracts, not execution support for types1/2/3.

## Adding support

Add a narrow schema, fixed API/adapter implementation, complete source effect and applicable topology proof, durable journal, created-ID/inverse model and recovery path. Validate newly admitted behavior on a disposable project before describing it as live-tested. Do not route a refusal through raw JavaScript or native UI to evade a failed invariant.
