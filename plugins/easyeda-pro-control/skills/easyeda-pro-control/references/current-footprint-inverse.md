# Disposable footprint inverse and cold UI continuation

Use these tools in the pinned public-utilities profile on an explicitly
disposable fixture. Check the actual loaded catalog and request the input
schemas from `easyeda_control_api` using `current-footprint-inverse` and
`current-footprint-inverse-cold-ui`. Send each assembled request to the
corresponding `-validate` action before native work.

## Same-facade inverse

`easyeda_control_current_footprint_inverse` selects the genuine completed
and released [forward copy](current-footprint-forward-write.md) already
retained by this facade. The execute request uses
`easyeda-pro-control.footprint-inverse-control.v1` and pairs
`footprint-inverse-flow-<suffix>` with its original
`footprint-forward-flow-<suffix>`. Select the exact source operation ID and
review the independent confirmations for delete-triggered persistence,
ordinary opening, debugger pauses, cache effects and scoped manager absence.
No explicit Save is dispatched.

This is an implemented validation route, not a record of completed connected
forward-copy or saved-inverse acceptance. Its inventory status and offline
tests do not satisfy the same-facade completed-forward gate before allocation.

The controller retains the original writer through the native delete and
persistence path. Completion requires full closed SQL after writer closure,
a separately born manager read of the saved state, and original writer and
cold-helper release. Original SDK and service qualification uses read-only
metadata on the pinned sources. The result describes the retained native task
and saved outcome. Historical forward and inverse result versions retain
their original fields and values.

## Separate cold UI follow-up

`easyeda_control_current_footprint_inverse_cold_ui` selects the completed and
released original inverse with its original cold manager. The execute request
uses `easyeda-pro-control.footprint-inverse-cold-ui-control.v1` and pairs
`footprint-inverse-cold-ui-flow-<suffix>` with that exact inverse operation
ID. Its independent confirmations cover a new read-only generation, opening
and cache effects, inspector pauses and normal closure without explicit Save.

A completed continuation requires the original negative UI, manager and
worker result, normal close, original root and whole-Job exit, helper
release and complete closed SQL equality. Only the separately issued
cold-UI record can prove native UI task absence. The original inverse
receipt still reports its manager-only proof. Public SDK parity, whole
inverse verification, connected acceptance and ordinary-project support
remain outside this validation route.

## Inspect and recover the original operation

Execute reserves one attempt and returns while the original work runs.
Use `inspect` with the same control schema and operation ID. Treat a lost
response as an unknown result. Keep the original frontend, facade and
package through cleanup and publication. A replacement cannot reconstruct
the owner from a file, receipt or PID.

Use `cleanup` with `confirmOriginalJobsOnly:true` for the original
resources and `settle-publication` to settle its retained journal.
The [foreground manager](autonomous-controller-updates.md#original-footprint-inverse-continuations)
routes these actions to the original connection after an interruption.
Cleanup attempts are consumed before dispatch. Check original resource
closure and terminal journal status before retirement. Source checks,
compiled helpers and inspect states do not constitute a saved and reopened
connected test.
